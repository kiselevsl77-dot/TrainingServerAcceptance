# BACKPORT.md — наработки пульта для основного UI

Пульт испытаний — временный проект, но часть его кода полезна основному
приложению (`TrainingServerUI`). Ниже — что и когда переносить.

## Готово к переносу сейчас (T0)

| Что | Куда | Зачем |
|---|---|---|
| `client/tasks.py` | `client/tasks.py` основного UI | модуль `Task service` ещё не реализован в основном UI (этап 7, FR-8); методы покрыты тестами `tests/unit/test_tasks_api.py` |
| `client/datasets.py` | `client/datasets.py` основного UI | датасеты — этап 3 (FR-4); тесты `tests/unit/test_datasets_api.py` |
| `acceptance/logging_setup.py` | `lib/` или `ui/common/` основного UI | в основном UI логирование объявлено, но не сконфигурировано (ни одного `logger.add`): нет файла, ротации и структурного журнала |
| `acceptance/http_log.py` | `ui/common/` или `lib/` основного UI | логирующий транспорт httpx: прозрачность запросов к серверу и доказательная база для отчётов |

## Порядок переноса (рекомендация)

1. Перенести `client/tasks.py` и `client/datasets.py` вместе с их unit-тестами
   (адаптировав импорты и фикстуры основного репозитория).
2. Перенести логирование: `logging_setup` (без части сессий) + `LoggingTransport`
   в `ui/common/`, включить файловые sinks в `ui/app.py`.
3. После этапов 3/7 основного UI — сверить реализации датасетов/задач с пультом
   и удалить дублирующий код.

## Что переносить не нужно

| Что | Почему |
|---|---|
| `acceptance/session.py`, `acceptance/notes.py` | артефакты испытаний (сессии, реестр замечаний) — принадлежность пульта, а не продуктивного UI |
| `acceptance/checks/**` | чек-лист испытаний относится к приёмке сервера |
| `acceptance/ui/pages/{stand,logs,records,checks,console,report}.py` | испытательные экраны; продуктовые FR-1…FR-8 реализуются отдельно |
| KPI/снимки стенда | нужны для отчёта об испытаниях |

## Что зафиксировано в замечаниях к API по итогам T0

Дефекты и пробелы, подтверждённые при работе над T0 (см. `acceptance/notes.py`,
`KNOWN_DEFECTS`): `latin-1` при скачивании, отсутствие `Range`/`Content-Length`,
игнорирование `limit`/`offset`, отсутствие `phase_connection`/рабочего `ph_n`,
отсутствие сущности «запись/субдатасет» и связи «датасет ↔ файлы», отсутствие
`task_id` в ответе `fill`, типы `H5`/`REPORT_ZIP` вне перечисления,
`DELETE /api/{file_id}` в корне `/api/`, пустые `signals` у моделей.
