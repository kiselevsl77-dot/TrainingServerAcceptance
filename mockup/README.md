# Прототип целевого интерфейса ПУЛЬТА (`mockup/`)

Кликабельный макет к комплекту документов:

* `docs/15. ТЗ на Пульт испытаний (целевое, по концепции).md` — требования;
* `docs/16. Макет интерфейса ПУЛЬТА (целевые экраны).md` — описание экранов `SCR-01…SCR-15`.

## Как открыть

Двойной щелчок по `index.html` (или «Open with → браузер»). Сборка не нужна, интернет не
нужен: все данные — в `demo-data.js`, внешних ссылок нет.

## Что можно проверить руками

| Действие | Где | Что демонстрирует |
|---|---|---|
| Двухколоночный редактор набора | `SCR-14` Наборы проверок | каталог слева ↔ состав справа, «＋ добавить отфильтрованные (N)», порядок ↑↓, KPI набора |
| Статус проверки в текущей сессии | `SCR-14`, колонка каталога | видно, что уже пройдено (только чтение), и что повтор даст историю (`FR-P-36`) |
| Ревизия и утверждение набора | `SCR-14` | «Сохранить ревизию» повышает номер, «Утвердить» фиксирует автора и статус (`FR-P-66`, `FR-P-67`) |
| Объединение наборов по ИЛИ | `SCR-15` Программа сессии | проверка из двух наборов попадает в программу **один раз**, происхождение видно («из: Н-01, Н-02») |
| Покрытие разделов | `SCR-15` | матрица «в программе / всего» против объёма, ⛔ непокрытые разделы |
| Утверждение с сокращением | `SCR-15` | без обоснования программа не утверждается (`FR-P-69`); обоснование попадает в карточку |
| Шаблоны и ревизии программы | `SCR-15` | «полная» / «смоук» / «регресс», «➕ Новая ревизия» + дельта с предыдущей |
| «▶ Следующая: `TC-…`» | `SCR-05` Прогон | **одна** команда запуска: отправляет ровно один пункт и называет его (`IR-P-4`, `IR-P-20`) |
| Маркеры очереди | `SCR-05` | «следующая», «выполняется», «последняя» — видно, что запустится и что только что прогнали |
| Состав очереди не редактируется | `SCR-05` | нет галочек; только «снять с причиной» (результат) и «изменить программу →» (планирование) |
| «▶▶ Пачка tech» / «⏯ Авто» | `SCR-05` | пачечный и авто-прогон с паузой; авто останавливается на пункте, требующем оператора |
| Карточка запуска | `SCR-05` (класс `live`/`heavy`) | гейт: без цели, данных и подтверждения пуск невозможен |
| Селекторы «запрос»/«ответ» | `SCR-05`, лента | **независимая** подробность запроса и ответа (`FR-P-21`) |
| «повторить с правками» | запись ленты | правка пути/тела и повтор вызова |
| Команд запуска нет в планировании и протоколе | `SCR-14`, `SCR-15`, `SCR-08` | правило одной команды (`IR-P-4`): запуск только на «Прогоне» |
| Ручная отметка | `SCR-08` | без заключения отметка не принимается (`FR-P-32`); «вне программы» — отдельная колонка |
| Снимок | `SCR-02` | состояние реестров «Начало»/«Окончание» и дельта |
| Состояния UI | верхняя панель | пусто / загрузка / ошибка / нет сессии (`IR-P-8`) |
| Навигация | сайдбар | 5 групп: Планирование испытаний → Подготовка → Испытания → Результаты → Инструменты (`IR-P-1`); `$Задачи` — последние в «Испытаниях» |

> Числа в демонстрационных данных уменьшены относительно примеров в `docs/16`: каталог — 28
> проверок (реальный — 69), программа — из 5 наборов. Логика расчётов в прототипе настоящая:
> объединение, дедупликация, покрытие, дельты ревизий считаются из данных (`demo-data.js`).

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | каркас: верхняя панель (состояние программы), сайдбар, рабочая область, тост |
| `styles.css` | оформление (три зоны, статусы, таблицы, лента обменов, маркеры очереди) |
| `demo-data.js` | демонстрационные данные: стенд, сессия, реестры, задачи, каталог проверок, **разделы, наборы и программа сессии**, обмены, замечания |
| `app.js` | реестр экранов `SCR-01…SCR-15`, маршрутизация `#scr-05`/`#scr-14`, отрисовка, планирование (объединение по ИЛИ, покрытие, ревизии) и симуляция прогона |

## Ограничения прототипа

* Данные статичные (демонстрационные), запросы к стенду не выполняются — обмены
  симулируются с задержкой, чтобы показать механику прогона.
* Выгрузки (CSV/MD/JSONL) — заглушки: показывают состав, файлы не формируются.
* Прототип не связан с рабочим кодом ПУЛЬТА (`acceptance/**`) и не заменяет его:
  это эталон для сверки «код ↔ макет ↔ ТЗ» (следующий этап — аудит соответствия).
