## Предлагаемый критерий «приложение работает на 70%»

1. **15 экранов показывают реальные данные** (не скелет), включая `SCR-201`, `SCR-405`, `SCR-102`, `SCR-101`, которых в старом UI не было.
2. **Сквозной процесс на стенде проходит целиком**: наборы → программа → утверждение → «▶ Следующая» → карточка проверки → протокол → отчёт (комплект) → замечания → журнал.
3. **Прогон**: режимы «сценарием/по вызовам», «Пачка tech», «Авто с пауза», карточка запуска как гейт, маркеры «следующая/выполняется/последняя», снятие с причиной, повтор с историей.
4. **Окружение**: стенд со снимками, сессия с реквизитами, данные стенда (файлы/записи/нагрузки/датасеты), `$Задачи` с FSM-1, консоль с подтверждениями и диагностика.
5. **Гейты**: смоук всех 15 экранов + unit-тесты экранов и компонентов + один смоук-«вертикальный срез» на подменённом стенде; pytest/ruff/mypy/gen_endpoints/node — зелёные.

**Остаётся на 30%** (после них — документация): справка «?»/`docs/17` + `help/`, полное «Сравнение сессий и регресс» (`SCR-405`), раздел отчёта «Программа и объём» + `programme.csv`, `docs/12` + трассировка, T6–T11.

## Тесты и что берём из старого кода

* **Тесты**: на каждый экран — unit-тесты его чистых хелперов (без Streamlit) + расширение `tests/smoke/test_app_smoke.py` проверками экрана; плюс один смоук-тест «вертикальный срез», который через `AppTest` проходит набор → программа → утверждение → «Следующая» → протокол (единственный гейт, который реально ловит «экран есть, а процесс не идёт»). Заготовка подменённого стенда — из `git show pre-bigbang:tests/smoke/test_app_smoke.py` (там уже есть ответы почти на все эндпоинты).
* **Переиспользуем знание, не код**: фильтры/поиск и curl-предпросмотр (`pages/monitor.py`), таблица задач и FSM-1 (`pages/tasks.py`), объединение записей и манифест (`pages/records.py`), выбор операции консоли и подтверждения (`pages/console.py`), реестр замечаний (`pages/notes.py` + `common/api_notes.py`), комплект отчёта (`pages/report.py`). Всё переписывается под `queue`/`runner`/`results`/`programme` — статус проверки берётся **только** из `results.py` (`DR-P-5`), состав программы правится **только** на `SCR-102` (`IR-P-18`), команда запуска одна (`IR-P-4`) — на эти инварианты держим тесты.

## Риски

1. **Объём**: пульта-наполнения ≈ 350 КБ старого UI + 4 новых экрана → это самый большой этап; митигируем шагами и повторным использованием компонентов.
2. **Демонстрация во время этапа**: до 3.5 пульт частично пуст — предлагаю после каждого шага обновлять скелеты только тех экранов, что готовы (остальные остаются явными заглушками).
3. **«Двойной учёт»**: соблазн хранить статус в очереди/программе — запрещено, держим тестами (иначе протокол разъедется с прогоном).
4. **Живой стенд**: проверки `live`/`heavy` требуют ресурсов — на них только ручная проверка по согласованию (`TC-…` с карточкой запуска).
