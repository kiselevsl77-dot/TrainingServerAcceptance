## Шаг 3.3. Фильтр RAW/markup по датасету (Q1 = б, Q6 = а)

Ядро и view (`pult/view.py`):
* `file_rows(files, *, ids=None)`, `record_rows(overview, *, ids=None, limit=200)` — фильтр по `id` файла (`raw_id`/`markup_id` строки манифеста, имя — запасной ключ);
* новый `rows_view(rows, *, limit)` → `{rows, shown, total, label: "показано 200 из 388", can_show_all: true}` (весь счёт — Python, JS печатает строку);
* новый `dataset_filter_view(...)` — блок `filter`: имя датасета, источник факта и достоверность («сервер» / «задача наполнения» / «факт пульта» / «гипотеза»), числа файлов/RAW/markup, `applied` + причина, `options` (все датасеты + «весь реестр» + «вне датасетов»), `sources` (auto/server/server_task/local/heuristic), `unavailable` (у каких датасетов состав не прочитан);
* `data_sections(data)` — счётчики/подписи подразделов (см. 3.2).

Пульт (`pult/server.py`, `api_data`):
* `?dataset=<id>` — состав читается **только для выбранного** датасета (`composition_api.read_composition(..., mode=query.source or auto)`, как сейчас в `_compositions`), отдаётся готовый блок `filter`, строки файлов/записей уже отфильтрованы;
* `?dataset=none` (**ответ б**) — «файлы вне датасетов»: читаются составы **всех** датасетов, фильтр показывает файлы, не попавшие ни в один; в блоке `filter` честно указано, сколько составов прочитано и у каких датасетов он недоступен; результат кэшируется в `PultState` (ключ `compositions|all`, TTL 60 с, сброс по `refresh`);
* честность: состав недоступен → **фильтр не применяется**, в `filter.note` прямо «состав недоступен (P1): показаны все файлы реестра», плюс переключатель источника (`source=local|heuristic`) — то, что уже умеет `read_composition` (`dataset_composition.py:994–1091`);
* `?limit=` (по умолчанию 200, `0` = все) для `$Файлы` и записей; `sections` отдаёт «показано N из M» и признак «есть что показать».

Интерфейс (`pult/web/index.html`, `app.js`, `styles.css`):
* строка фильтра над `$Файлы`: селект датасета, селект источника, кнопка «🔍 показать файлы и записи этого датасета», «сбросить», кнопка «показать все (388)» у переполненных списков;
* выбранный датасет виден в подписи зон `$Файлы` и «Записи RAW + markup»; выбор переживает автообновление — в `resultsView` (как `resultsView.composition`, `app.js:609`), уходит в `resultsQuery()` как `dataset=…&limit=…&source=…`.

Тесты: `test_pult_view.py` (фильтр строк, счётчик, блок `filter` при недоступном составе, «вне датасетов»); `test_pult_server.py` (расширенный подменённый стенд: 2 датасета, файлы, задача `dataset-fill` — `?dataset=` меняет состав зон; состав недоступен → фильтр не применён и это сказано; `?limit=200` → «показано 200 из 388», `?limit=0` → все); живая проба на стенде: **388 → 104 файла для `skfu-train`**.

## Шаг 3.4. Датасет и модель для ML + подстановка в тело (Q4 = а, Q5 = а)

Ядро:

* `pult/web/app.js`: селекты в карточке рисуются из `field.options`; при `next.ml` рисуется панель «Параметры проверки» (датасет/модель), значения уходят в `params` при `next`/`call`; ничего не считается в JS.

# Риски и границы (прямо, без «потом посмотрим»)

1. **Подстановка плейсхолдеров работает только на верхнем уровне тела**: `post /api/datasets/fill/{dataset_id}` (список `raw_file_ids`) и AutoML (`range`) не затрагиваются — это осознанное правило, закрепляю тестом.
2. **Если у пункта задано собственное тело (`values["body"]`), выбранный датасет в него не попадает** — правило приоритета сохраняется; в интерфейсе это будет видно в «Что будет отправлено».
3. **`model_id` / `dataset_id` для AutoML (`train_dataset_id`, `test_dataset_id`) в этот шаг не входят** (это отдельный этап, вопрос 2 файла 47).
4. **Без UI-кнопки «по вызовам» ML-проверку из пульта не запустить**: «▶ Следующая» на проверке без сценария отказывает (M0-гейт), а `action=call` интерфейс сегодня не вызывает. Либо добавляем минимальную кнопку в этом шаге, либо живая проба делается через API и «повтор вызова» из ленты — это вопрос №1.

## Порядок работ (4 коммита + отчёт)

1. Вкладки: порядок `Планирование, Сессии, Прогон, Результаты, Лента обмена`, старт — «Планирование» + страж порядка.
2. «Данные стенда»: `<details>` по подразделам (свёрнуты по умолчанию), счётчики из Python, кнопки «Свернуть/Развернуть все», состав внутри `$Датасеты`, новый `$Модели`.
3. Фильтр RAW/markup по датасету: `?dataset=` / `?dataset=none` / `?source=` / `?limit=`, блок `filter`, счётчик «показано N из M» + «показать все».
4. Датасет и модель: карточка запуска + панель параметров, `_json_body` подставляет плейсхолдеры, предпросмотр ML, `$Модели` в API, доказательства.
