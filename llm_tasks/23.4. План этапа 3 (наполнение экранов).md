## 1. Ответы заказчика и решения

| № | Вопрос | Ответ | Как учитываем |
|---|---|---|---|
| 1 | Критерий «70%» | «70%» — метафора, а не порог; нужен предъявляемый результат уже завтра; приложение может быть функциональным не для всех проверок (обучение модели, AutoML — позже); документация — по отдельному запросу | работаем по приоритету: сначала сквозной срез, затем остальные экраны; руководство (`docs/12`) не трогаем |
| 2 | Порядок наполнения | (а) планирование → сессия/стенд → прогон → результаты → данные/инструменты | порядок сохранён; техническое уточнение: программа живёт **в сессии** (`programme.save_programme(session, …)`), поэтому «Сессия» идёт перед программой |
| 3 | `SCR-405` на этом этапе | (а) минимально: дельта результатов между двумя сессиями | полный объём (регресс, дельта замечаний и снимков) — после среза |
| 4 | Справка «?» | (а) отложить до этапа 5 (`docs/17` + `help/`) | на экранах — только подписи и подсказки полей |
| 5 | Глубина тестов | (а) unit чистых хелперов + смоук по экрану + смоук-«вертикальный срез» | компоненты пишутся с чистыми функциями, чтобы их можно было проверить без Streamlit |
| 6 | Проверка вручную | (а) подменённый стенд в тестах, живой — по согласованию | «демо-режима» внутри приложения нет |

## 2. Критерий «приложение работает» (ориентир, не порог)

1. Все 15 экранов показывают реальные данные (не скелет).
2. Сквозной процесс: наборы → программа → утверждение → «▶ Следующая» → карточка проверки →
   протокол → отчёт → замечания → журнал.
3. Прогон: «сценарием/по вызовам», «Пачка tech», «Авто с паузой», карточка запуска, маркеры
   «следующая/выполняется/последняя», снятие с причиной, повтор с историей.
4. Окружение: стенд со снимками, сессия с реквизитами, данные стенда, `$Задачи`, консоль.
5. Гейты зелёные: `pytest`, `ruff check`, `ruff format --check`, `mypy`, `gen_endpoints --check`,
   `node --check`, смоук всех экранов + смоук-«вертикальный срез».

## 4. Инварианты, которые проверяются тестами

* единственный источник статуса проверки — `results.py` (`DR-P-5`): очередь и программа
  статус не хранят;
* состав программы правится только на `SCR-102` (`IR-P-18`): экран «Прогон» даёт ссылку
  «изменить программу», но не редактирует состав;
* команда запуска одна — «▶ Следующая: `TC-…`» (`IR-P-4`), на остальных экранах только переходы;
* изменяющие проверки (`live`/`heavy`) без карточки запуска не запускаются (`FR-P-19`);
* схема сессии остаётся `v7` — наполнение экранов новых полей не вводит.
