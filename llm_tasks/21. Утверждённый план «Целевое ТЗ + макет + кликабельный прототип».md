## 2. Что именно будет уметь прототип (проверка концепции «руками»)

* **`SCR-05 «Прогон»** — главный экран: очередь с фильтрами и «следующим тестом» сверху; блок «Пуск» (один тест / пачка `tech` / авто с паузой / стоп); **лента обмена**, где запрос и ответ показаны **по раздельности** с независимой подробностью; `curl`; «повтор с правками».
* **Симуляция прогона**: нажатие «Пуск» добавляет в ленту обмен с задержкой, считает вердикт «соответствует / не соответствует ожиданию», обновляет счётчики очереди и протокола; пункт «тяжёлой» проверки останавливается на карточке запуска (цель, данные, ответственный, судьба артефактов, подтверждение расхода).
* **`SCR-06`**: лента и диапазон журнала раскрываются **внутри** карточки проверки — без ухода на другой экран.
* **`SCR-08 «Протокол»**: KPI по выборке, ручные отметки (`выполнена вручную` / `пропущена` / `блокировано API` / `прервана`) с обязательным заключением, выгрузки — и **ни одной кнопки «Пуск»** (anti-goal «один пуск»).
* **`SCR-01 «Обзор»**: индикатор фазы процесса 0–4, прогресс очереди, открытые замечания по `P0/P1/P2`, готовность отчёта.
* **Состояния**: пусто / загрузка / ошибка / нет сессии / частичные данные — с реальными текстами сообщений (это часть требований `IR-P-*`).
* **Навигация**: 4 группы ровно в порядке концепции; `$Задачи` — последние в «Испытаниях»; консоль и диагностика — в «Инструментах».
