# Фиксы «Ленты обмена» — что сделано

Готово. Оба ваших замечания закрыты, поведение проверено живым headless-браузером
(не только HTTP-тестами). Ниже — факты и точные формулировки, чтобы вы могли поправить
слова, если они не подходят.

## Что было не так

1. **«(тело не сохранилось)» у обычного `GET`** — это была неверная подпись, а не потеря
   данных: у четырёх обменов вашего прогона `TC-SYS` `request_bytes: 0` (тела нет вовсе),
   журналирование тел включено (`PULT_LOG_BODIES` не задан → умолчание `true`), а JS печатал
   одну и ту же заглушку для **любого** пустого тела. Отсюда «везде».
2. **Раскладушка закрывалась сама** — автообновление раз в 15 секунд (`window.setInterval`)
   пересобирало все строки ленты (`box.textContent = ""`), поэтому открытая запись
   закрывалась. Там же терялись правки в «⧉ повторить с правками» и ввод в карточке запуска.

## 1. Подписи про тело считает сервер

Правило архитектуры B («JS ничего не считает») соблюдено: браузер печатает готовый текст.

* `pult/view.py::body_note()` — новая функция, разбирает пять ситуаций и получает `method`
  (у `POST` без тела подпись не должна упоминать `GET/HEAD`);
* `pult/view.py::journal_row()` → новые поля `request_note` и `response_note`
  (и такие же параметры у `journal_rows`);
* `pult/server.py::api_journal` — передаёт `log_bodies` и `body_limit` из настроек пульта и
  отдаёт в ответе `bodies_logged`, чтобы интерфейс мог сказать «тела не сохраняются» на
  уровне шапки ленты;
* `pult/web/app.js::renderJournal` — печатает `request`/`response`, а если тела нет — готовую
  подпись (`text(body) || text(note)`), и **не** выдумывает текст сама.

Итоговые формулировки (проверены тестами и живой страницей):

| Ситуация                                | Что видит оператор                                                       |
| --------------------------------------- | ------------------------------------------------------------------------ |
| `GET`/`HEAD`/`OPTIONS`, тела нет        | «тела нет: запрос без тела (GET/HEAD)»                                    |
| `POST`/`PUT`/`PATCH`, тела нет          | «тела нет: запрос отправлен без тела»                                     |
| ответ без тела (`204`, пустой)          | «тела нет: ответ без тела (204 или пустой ответ)»                          |
| `multipart/form-data` (размер есть)     | «тело не сохраняется: multipart/form-data, 512 байт (смотрите размер)»     |
| не текстовый формат (размер есть)       | «тело не сохраняется: не текстовый формат, 4096 байт (смотрите размер)»    |
| тело есть                              | подписи нет — печатается само тело                                        |
| журналирование тел выключено            | «тело не сохранялось: журналирование тел выключено (`PULT_LOG_BODIES`)»    |
| тело обрезано лимитом                   | тело + «тело обрезано по лимиту 4096 символов»                             |

В заголовке строки ленты (`<summary>`) теперь тоже видно короткую причину, если тела нет, —
запись понятна, не раскрывая её.


## 2. Автообновление больше не мешает работе

`pult/web/app.js`:

* **Состояние переживает перерисовку**: `journalView = { open, drafts }` (открытая запись и
  черновики пути/тела повтора), `runView.drafts` (незаполненная карточка запуска и текст
  ручной отметки). После перерисовки запись остаётся раскрытой, а набранное — на месте;
  черновик очищается, когда правка отработана (карточка сохранена/запущена, отметка записана).
* **Пока оператор вводит — панель не трогаем**: `busyTyping()` смотрит на фокус; если он в
  `input`/`textarea`/`select`, автообновление обновляет только шапку (`/api/state`: фаза,
  строка «что дальше»), а панель ждёт, пока фокус уйдёт из поля.
* **Галочка «автообновление» в шапке** (`#auto-refresh`, по умолчанию включена): можно
  «заморозить» экран, пока читаешь длинный ответ; выключение и включение подтверждается
  сообщением в строке состояния. Кнопка «Обновить» работает всегда.
* Интервал зовёт `autoRefresh()`, а не `refresh()` напрямую — правила выше применяются
  в одном месте.

## 3. Ссылка на запись ленты `#journal/12`

* `panelFromHash()` возвращает `{ panel, argument }` (адрес вида `#journal/12`);
* `showPanel(name, argument)` раскрывает нужную запись и держит её открытой
  (`journalView.open`), так что ссылку можно переслать разработчику, и адрес переживает
  автообновление;
* в раскрытой записи есть кнопка **«⛓ ссылка на запись»** — она ставит адрес и показывает
  полный URL в строке состояния (удобно скопировать в замечание);
* `hashchange` учитывает аргумент: переход по `#journal/N` из уже открытой вкладки тоже
  раскрывает запись.

## Живая проверка браузером (протокол фактов)

Проверял не только HTTP-тестами: поднял пульт на отдельном порту **8513** с подменённым стендом
(`httpx.MockTransport`) и открыл страницу проверки в `chrome --headless=new
--virtual-time-budget=200000 --dump-dom` (виртуальное время: два полных цикла автообновления
проходят за секунды). Пульт заказчика на 8502 не тронут — на этом порту оказалось два
слушателя (`SO_REUSEADDR`), свой я снял.
