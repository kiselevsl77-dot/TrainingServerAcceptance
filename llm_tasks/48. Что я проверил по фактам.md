## Задача 1. Работа с датасетами

### 1а. Фильтр RAW/markup по датасету

| Слой      | Что делается                                                 |
| --------- | ------------------------------------------------------------ |
| Ядро      | `pult/view.py`: `file_rows(files, dataset_ids=None)`, `record_rows(overview, dataset_ids=None, limit=…)` — строки остаются теми же, фильтр по `id` файла (`raw_id`/`markup_id` в манифесте; имена — запасной ключ); счётчик «показано N из M» |
| Пульт     | `GET /api/results?dataset=<id>` (и `/api/data?dataset=`): сервер читает состав **только выбранного** датасета (`read_composition`, `auto`) и отдаёт готовый блок `filter`: имя датасета, источник факта и достоверность (`сервер` / `задача наполнения` / `факт пульта` / `гипотеза`), числа файлов/RAW/markup, применён ли фильтр и почему нет |
| Честность | состав недоступен → **фильтр не применяется**, в интерфейсе прямо: «состав недоступен (P1): показаны все файлы реестра» + возможность переключить источник (`local`/`heuristic`) — как уже умеет `read_composition` |
| UI        | в строке `$Датасетов` — кнопка «🔍 показать файлы и записи этого датасета», рядом с текущим фильтром — «сбросить»; выбранный датасет в подписи зон `$Файлы` и «Записи RAW + markup»; выбор переживает автообновление (как `resultsView.composition`) |
| Тесты     | `test_pult_view.py` (фильтр строк и счётчик), `test_pult_server.py` (`?dataset=` меняет состав зон, состав недоступен → фильтр не применён и это сказано), плюс живая проба на стенде (388 → 104 файла для `skfu-train`) |

### 1б. Выбор датасета для команд ML (обучение/инференс)

| Слой         | Что делается                                                 |
| ------------ | ------------------------------------------------------------ |
| Карточка     | новое поле **«Датасет для проверки»** (`dataset_id`) в `acceptance/run_card.py`; опции — из стенда (`datasets.list_datasets()`, Python-подписи «имя · файлов N · RAW/M»); читается **только когда проверке нужен датасет** (в её вызовах есть `dataset_id`), чтобы страница прогона не зависела от стенда зря |
| Связка       | сервер сам подставляет выбранный датасет в `params` при `action=next|call` (JS ничего не решает), значение хранится в `run_cards[check_id]` и переживает перерисовку; в поле «Данные, на которых выполняется» подставляется «датасет «skfu-train» (104 файла), сессия …» → это попадает в **доказательства** результата и в протокол |
| Ядро         | `runner._json_body`: подстановка известных параметров в тело по заготовке спецификации (в шаблоне `"dataset_id": "<uuid>"` → выбранный id; правило — только плейсхолдеры `"<…>"`, остальное не трогаем); ошибок не добавляет, `values["body"]` по-прежнему главнее |
| Предпросмотр | `acceptance/test_payloads.py`: ветка для операции обучения/инференса — «Что будет отправлено» перестанет писать «проверка ничего не создаёт» для `TC-TR-02`/`TC-INF-01`, а покажет `POST …/train` с датасетом и параметрами |
| Тесты        | `test_run_card.py` (поле и валидация), `test_runner.py` (подстановка в тело: выбранный датасет уходит в JSON, а не плейсхолдер), `test_pult_view/server` (опции в карточке, `params` собирает сервер), `test_test_payloads.py` (предпросмотр обучения) |

**Смежное, без чего ML-команды всё равно не уйдут:** в пути `train`/`inference`/`check` нужен **`model_id`**. Механика та же самая: поле «Модель» (селект, если модели есть; иначе текстовое поле + подсказка «сначала `TC-MOD-02`»). На стенде моделей 0, поэтому предлагаю сделать оба поля сразу — иначе обучение выбрать датасетом нельзя.

## Задача 2. Сворачивание подразделов «Данные стенда»

* Четыре подраздела (`$Файлы`, «Записи RAW + markup», `$Нагрузки`, `$Датасеты и состав`) оборачиваются в нативный `<details>/<summary>` — состояние живёт в DOM, **переживает автообновление** (перерисовка трогает только `tbody`), JS-логики не добавляется (правило «JS ничего не считает» сохраняется).
* В заголовке подраздела — счётчик из Python (`$Файлы · 388`, «Записи RAW + markup · 129», «$Датасеты · 7»), он остаётся виден и в свёрнутом виде.
* Строка KPI зоны и предупреждения остаются всегда на виду (это сводка), плюс кнопки «Свернуть все / Развернуть все».
* Панель состава датасета переезжает внутрь блока `$Датасеты` (чтобы не «висеть» внизу).
* Тесты: серверный тест на счётчики в заголовках и на `<details>` (структура страницы), как принято в `test_pult_server.py`.

## Задача 3. Порядок вкладок

`Прогон, Планирование, Результаты, Сессии, Лента обмена` → **`Планирование, Сессии, Прогон, Результаты, Лента обмена`** (одна правка `pult/web/index.html`), плюс тест-страж порядка (по образцу `test_app_js_declares_functions_at_top_level`): порядок кнопок в HTML обязан совпадать с согласованным списком. `panelFromHash.known` дополняется/остаётся; deep-link’и `#run`, `#results`, `#journal/N` продолжают работать.
