## 2. Отдельный проект `D:\VSC Python projects\TrainingServerAcceptance`

Отдельный git-репозиторий (2 коммита, 74 файла, рабочее дерево чистое): вендорная копия `client/`/`lib/` (commit `c71afef`, **без локальных правок** — фиксируется `VENDOR.md`), аддитивные `client/tasks.py`, `client/datasets.py` (`BACKPORT.md` — план переноса в основной UI), `tools/sync_vendor.ps1` (SHA-сверка копии с источником), `run_pult.bat`/`run_pult.sh` (порт 8502, своё `.venv` и `.env`), `acceptance_data/` (gitignored).

**Реализовано в T0:**
* **логирование** (`logging_setup.py`): консоль + `app.log` (ротация 10 МБ×10) + **`session_<id>.jsonl`** (`serialize=True`), контекст `session_id/check_id/module/event/payload`, событие `pult_started` пишется всегда; запись синхронная (`PULT_LOG_ENQUEUE=false`) — журнал испытаний не теряется при аварии;
* **журнал HTTP** (`http_log.py`): `LoggingTransport` (через уже существующий параметр `transport` в `ApiHttpClient`) + `Journal` — метод, путь, query, метка проверки, статус, мс, размеры, `Content-Type`, тела (text/json/csv до лимита; бинарь/multipart — только размером), ошибки соединения;
* **сессия испытаний** (`session.py`): `черновик → идёт → завершена`, поля для отчёта (программа-методика, объект/сборка, заказчик, организация, оператор, комиссия, цель, объём, условия, ограничения, критерии, подписи), снимки стенда начало/окончание, история событий, выгрузка/загрузка файла сессии;
* **экраны**: «Стенд» (health/version со всеми полями сборки, параметры, пути журналов, снимок реестров + сравнение), «Сессия испытаний», «Журнал» (фильтры по ошибкам/метке/подстроке, детали обмена, выгрузки, хвост `app.log`); заглушки T1–T5;
* **основа чек-листа и замечаний**: `checks/registry.py` (`CheckSpec/CheckResult/CheckStatus`, классы, FSM-совместимые статусы), `notes.py` — **11 готовых шаблонов известных дефектов** (P0/P1/P2) и **5 перспективных требований** с субдатасетом во главе.
