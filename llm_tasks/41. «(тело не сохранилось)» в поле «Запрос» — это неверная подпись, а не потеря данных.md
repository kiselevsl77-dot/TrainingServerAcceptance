## 1) «(тело не сохранилось)» в поле «Запрос» — это неверная подпись, а не потеря данных

Факты из журнала вашей сессии `acceptance_data/logs/session_20260926-000303-25c5.jsonl` (прогон 29.09 в 12:48):

```text
seq 3  GET /api/__test_unknown__                          request_bytes: 0  request_body: null
seq 4  GET /api/tasks/00000000-0000-4000-8000-000000000000 request_bytes: 0  request_body: null
seq 6  GET /api/data/files                                 request_bytes: 0  request_body: null
seq 7  GET /api/datasets/not-a-uuid                        request_bytes: 0  request_body: null
```

Все четыре обмена прогона `TC-SYS` — **GET, у которых тела нет вообще** (`request_bytes: 0`). Тела при этом пишутся: `PULT_LOG_BODIES` в `.env` не задан → действует умолчание `true`, лимит 4096 символов (`acceptance/config.py`). Пустое значение доходит до браузера как `""`, а JS печатает заглушку «(тело не сохранилось)» для **любого** пустого тела — отсюда «везде».

То же самое врущее сообщение появится ещё в трёх случаях: ответ без тела (204/HEAD), бинарное тело (сохраняется только размер) и выключенное журналирование тел.

**Что предлагаю:** тексты генерирует Python (правило архитектуры B), а браузер печатает готовое:

| Ситуация                     | Подпись из сервера                                           |
| ---------------------------- | ------------------------------------------------------------ |
| GET/HEAD, тела нет           | «тела нет: запрос без тела»                                  |
| ответ 204 / пустой           | «ответ без тела (204)»                                       |
| бинарные данные              | «тело не сохраняется: бинарные данные (1 024 байта), смотрите размер» |
| журналирование тел выключено | «тело не сохранялось: журналирование тел выключено (`PULT_LOG_BODIES`)» |
| тело обрезано лимитом        | текущее тело + пометка «тело обрезано по лимиту 4096 символов» |

Место правки: `pult/view.py::journal_row` (добавить `request_note`/`response_note`), `pult/server.py::api_journal` (передать `log_bodies` из настроек), `pult/web/app.js::renderJournal` (печатать готовую подпись).

## 2) Раскладушка закрывается сама — виновато автообновление раз в 15 секунд

`pult/web/app.js` в конце: `window.setInterval(refresh, 15000)`. Каждые 15 с `refresh()` → `loadPanel(active)` → `renderJournal()` **пересобирает все строки ленты заново** (`box.textContent = ""` и новые `<details>`), поэтому открытая запись закрывается. Там же теряются правки, набранные в «⧉ повторить с правками», и текст, набранный в карточке запуска на «Прогоне» (форму тоже перерисовывают из данных сервера).

**Что предлагаю (три уровня, все вместе):**

1. **Состояние интерфейса переживает перерисовку**: открытая запись ленты, черновики пути/тела в «повторе», незаполненная карточка запуска и текст отметки хранятся в JS и восстанавливаются после обновления.
2. **Не трогать панель, пока оператор вводит**: если фокус в поле ввода, автообновление обновляет только шапку (фаза, «что дальше»), а панель не перерисовывает. Плюс галочка «автообновление» в шапке — можно «заморозить» экран, когда читаешь длинный ответ.
3. **Ссылка на запись ленты** `#journal/12`: адрес открывает нужную запись и она не закрывается. Это и удобно (переслать обмен разработчику), и даёт мне способ проверить фикс браузером: открыть `#journal/6`, прокрутить 30 с виртуального времени (две перерисовки) и убедиться, что запись осталась открытой.

Тесты: `journal_row` (пять ситуаций подписи) и `GET /api/journal` (подпись при выключенном журналировании); смоук-срез — строка GET имеет `request == ""` и непустой `request_note`; браузерная проверка с `#journal/N` и двумя циклами автообновления; гейты как обычно.
