Готово. Итог по правке «статус в списке задач и смежные атрибуты».

## Что сделано

**1. Колонка «Статус» + смежные (0 запросов к серверу)** — `acceptance/tasks_monitor.py`, `acceptance/ui/pages/tasks.py`
Новый метод `TaskMonitor.observation_index(session)` (индекс наблюдений по `task_id`), таблица списка теперь:

| Задача | Тип  | **Статус** | **Наблюдается** | **Проверка** | Название | Описание | Создана | **Прошло** | **Обновлён** |
| ------ | ---- | ---------- | --------------- | ------------ | -------- | -------- | ------- | ---------- | ------------ |

* «Статус» — `иконка + подпись` последнего опроса (`session.tasks`), для ненаблюдаемой — «— не наблюдалась»; после опроса задачей становится «🟢 Выполняется» и т. п.;
* «Наблюдается» (⏱️ да/—), «Проверка» (`check_id`), «Прошло» (от `created_at`), «Обновлён» (`poll.last_poll`);
* «Описание» усечено до 40 символов, чтобы таблица не разъезжалась;
* подпись под таблицей объясняет политику и что статус в списке API не отдаёт.

**2. Кнопка «⤓ Подтянуть статусы (N)»** — `acceptance/ui/state.py`, `acceptance/ui/pages/tasks.py`
Новая кэшируемая `state.load_task_statuses(task_ids)`: карточки `GET /api/tasks/{id}` параллельно (`STATUS_FETCH_WORKERS=5`), лимит 100 задач, кэш 15 с, отдельные статусы и ошибки по каждой задаче. Кнопка **требует подтверждения** (чекбокс, как у изменяющих операций), запросы идут под меткой **`TC-TASK-02`**, результат показывается в таблице, пишется событие `task_statuses_refreshed`, а `refresh_tasks()` (кнопка «Обновить список») сбрасывает и кэш статусов.

**3. Два дефекта, найденных по ходу**
* **Дубль «на странице»**: на вкладке было два селектора размера страницы, второй инертный. `render_pagination(..., show_size=False)` убирает его; смоук-тест следит, что остался только `tasks_per_page`.
* **Метка проверки не доходила до параллельных запросов**: метка/`check_context` живут в `contextvars`, а потоки пула их не наследуют — теперь контекст копируется (`copy_context()` + `Context.run`) и передаётся каждому запросу. Проверено живьём: **метка `TC-TASK-02` на 10 из 10** запросов карточек.

## Что важно знать про поведение

* Статус из наблюдения — **последний известный** (может быть старым): чтобы обновить, используйте автоопрос/«Опросить все сейчас» или «⤓ Подтянуть статусы»; под кнопкой видно время последнего подтягивания.
* «Подтянуть статусы» **не** ставит задачи на наблюдение (история FSM-1 и поллинг не создаются) — это отдельное осознанное действие, потому что это N+1 запрос (≈ 0,7 с на 10 задач, до 100 задач за раз).
* Статусы страницы держатся до «⟳ Обновить список» (сбрасывает и кэш списка, и кэш статусов).
* Пробел API («нет статуса в списке», «нет сортировки») — теперь это зафиксированный результат испытаний с замерами, а не незамеченная особенность; при появлении поля `status` в списке проверку `TC-TASK-02` и таблицу можно упростить — живой тест `test_live_task_list_has_no_status_but_card_has` сразу покажет, что N+1 больше не нужен.
