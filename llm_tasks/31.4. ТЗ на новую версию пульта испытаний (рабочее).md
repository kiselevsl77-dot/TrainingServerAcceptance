## 3. Архитектура

```text
pult/
  server.py     — stdlib ThreadingHTTPServer: JSON-API + отдача pult/web/**; фоновый поток для долгих операций
  state.py      — перенос glue из acceptance/ui/state.py: Runtime, Journal, клиент, журналирование, текущая сессия
  view/         — сборка view-моделей (перенос чистых функций: status, journal, run_card, snapshots) + тексты/подписи
  web/          — index.html, app.js, styles.css (на базе mockup/, demo-data.js заменён на fetch)
```

* **Правило:** вся бизнес-логика — в Python; JS не считает статусы, покрытие, дельты и не формирует подписи, а отображает готовые view-модели. Это позволяет проверять логику python-тестами и не писать JS-тесты.
* **Экранирование обязательно:** данные стенда (`file_name`, описания, тела ответов) выводятся только через `textContent`/эскейп-хелпер — в `mockup/app.js` сейчас `innerHTML` без escape (проверено, строки 259/299).
* **Долгие операции** (`fill`, `train`, инференс, `batch-tech` по большим выборкам): запрос ставит задачу в фоновый поток, API отдаёт `202 + job_id`, UI опрашивает `GET /api/jobs/{id}`; интерфейс не блокируется, сервер не держит один поток на операцию.
* **Запуск:** `python -m pult.server` (по умолчанию `127.0.0.1:8502`) + открытие браузера; `run_pult.bat`/`run_pult.sh` переключаются на эту команду; зависимости: `httpx`, `loguru`, `pydantic`, `python-dotenv` (Streamlit уходит).
* **Состояние:** сессия и журнал — на диске (`acceptance_data/`), как сейчас; сервер не хранит бизнес-состояние в памяти, поэтому перезапуск ничего не теряет (`NFR-P-7`).
