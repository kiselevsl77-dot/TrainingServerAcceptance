## Ответ на вопрос

**Нет, это не ожидаемый итог — это дефект, который я внёс в Step 1.** Страница обязана открываться как обычное локальное веб-приложение (`http://127.0.0.1:8502`): шапка, вкладки «Прогон / Сессии / Протокол / Лента обмена», работающие кнопки. То, что вы видите, — следствие одной строки кода, а не «пока так и должно быть».

## Причина (найдена, подтверждена кодом)

`pult/server.py`, метод `static()` (строки 147–163) возвращает статику в **том же** типе `Raw`, который предназначен для скачиваемых файлов, и всегда заполняет `filename`:

```python
158 |         mime = MIME_TYPES.get(candidate.suffix.lower(), "application/octet-stream")
159 |         return Raw(
160 |             candidate.read_text(encoding="utf-8"),
161 |             content_type=mime,
162 |             filename=candidate.name,      # ← имя файла задано всегда
163 |         )
```

а `_ok()` (строки 1007–1018) на непустой `filename` безусловно ставит заголовок скачивания:

```python
1013 |             self.send_header("Content-Length", str(len(body)))
1014 |             if result.filename:
1015 |                 self.send_header("Content-Disposition", f'attachment; filename="..."')
```

Проверка факта (без запуска сервера):

```
/           -> text/html; charset=utf-8    | Content-Disposition filename = 'index.html'
/styles.css -> text/css; charset=utf-8     | Content-Disposition filename = 'styles.css'
/app.js     -> text/javascript; charset=utf-8 | Content-Disposition filename = 'app.js'
```

Следствие: документ приходит как **вложение** — браузер его сохраняет, а не рисует; `styles.css` и `app.js` приходят с тем же заголовком, поэтому стили не применяются и скрипт не выполняется. Если открыть сохранённый `index.html` из папки загрузок, рядом нет ни `styles.css`, ни `app.js`, а `fetch("/api/state")` уходит в пустоту — ровно «без стилей, без интерактивных элементов».

## Почему гейты это пропустили (честно)

* `tests/unit/test_pult_server.py:206-217` и `:446-447` проверяют **тело** и `content_type` объекта `Raw`, но не заголовки живого HTTP-ответа;
* `Invoke-WebRequest` спокойно читает и «вложенный» ответ, поэтому моя живая проверка сервера выглядела зелёной;
* реального браузера в проверках не было — а именно браузер и есть «потребитель» этой страницы.

## Второй, пока скрытый дефект того же места

`static()` читает файл как **текст** (`read_text(encoding="utf-8")`), а `_ok()` кодирует его обратно. Сейчас в `pult/web` только текстовые файлы (`index.html`, `app.js`, `styles.css`), поэтому не проявляется; но первый же `.png/.ico/.woff2` (или `.svg` с не-utf8) даст `UnicodeDecodeError` → 500. Это стоит починить тем же заходом.

## План исправления (Act mode)

1. **Разделить «страницу» и «скачивание» в `pult/server.py`**
   * добавить в `Raw` признак скачивания (`download: bool = False`) и ставить `Content-Disposition` в `_ok()` **только** для него;
   * `static()` больше не передаёт `filename` — HTML/CSS/JS идут как обычные ресурсы; `Cache-Control: no-store` для статики, чтобы правка JS не «залипала» в кэше браузера;
