## 2. Итоговый состав T1

**Экран «Записи (RAW + markup)»** (`acceptance/ui/pages/records.py`), вкладки:
1. **Записи** — карточка записи: RAW (`id`, `size`, `import_date`, `s3_path`) + markup (те же поля), Δ времени импорта, правило (`по имени и времени импорта` / `только по имени` / `вручную`) и уверенность (подтверждено / не подтверждено / вручную), признак дубля и номер версии, число кандидатов; действия: скачать markup, скачать пару (zip, с подтверждением из-за RAW до 2.1 ГБ), «записи и чанки» (`parse_markup_stats`), привязать markup из кандидатов, снять привязку, исключить из испытаний, комментарий, «создать замечание к API».
2. **Дубли** — по каждой базе имени: все RAW и markup, их `size`/`import_date`/`s3_path`, различия; выбор «актуальной» записи (ручное решение) и явная отметка, что без `checksum`/`updated_at` однозначность недостижима (замечание к API).
3. **Несопоставленные** — «RAW без разметки» и «разметка без RAW» с причиной (нет кандидата; `404 latin-1` — «заблокировано API»).
4. **Прочие файлы** — `H5`, `REPORT_ZIP` (в записи не входят).
5. **Манифест** — предпросмотр, «Скачать CSV» (`utf-8-sig`), «Скачать JSON», «Сохранить в артефакты сессии» → `acceptance_data/artifacts/<session_id>_records_manifest.{csv,json}` + `session.artifacts` + событие `records_manifest_exported`.

**KPI:** файлов всего, записей, подтверждённых, «не подтверждено», ручных, дублей, без разметки, непарных, прочих, объём RAW/markup.

**Модули T1:** `acceptance/records.py` (модель `Record`, `RecordsOverview`, `RecordsStats`, `build_records`, `manifest_*`), `acceptance/overrides.py` (`records_overrides.json` — переиспользование между сессиями, аудит «кто/когда/в какой сессии»), правки `acceptance/ui/state.py` (кэш реестра), `acceptance/api.py` (снимок стенда: метрики записей), `acceptance/session.py` (`schema_version` 2: `artifacts[]`, `markup_stats{}` — аддитивно, старые файлы читаются), `acceptance/app.py` (название пункта меню).

**Журналирование:** события `records_loaded`, `record_pair_manual`, `record_unlink`, `record_excluded`, `record_markup_stats`, `records_manifest_exported`, `api_defect_observed`; все HTTP-вызовы действий — под меткой `REC:<record_id>`.

**Тесты:** unit (`records`, `overrides`, схема сессии v2), smoke `AppTest` по вкладкам и перепривязке, integration (живой реестр: ~265 файлов → ~62 записи, дубли `Antminer_S19`, подсчёт records/chunks для ASCII-markup, не-ASCII → «заблокировано» без падения). Автотесты — только read-only, без скачивания крупных RAW.
