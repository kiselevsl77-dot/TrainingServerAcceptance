## Диагноз: что именно «утяжеляет» (и это не только Streamlit)

1. **UI написан императивно на Python.** Streamlit перерисовывает весь скрипт на каждый клик: любое действие = виджет + `st.rerun()`. Приёмы, которые в макете бесплатны (двухколоночный редактор набора с ↑↓, независимые селекторы подробности «запрос/ответ», лента с раскрытиями, inline-правка и повтор вызова, маркеры очереди), приходится эмулировать в Python — отсюда 5 402 строки экранов и 30–37 КБ на экран.
2. **Тесты дороже кода.** 11 650 строк тестов против 11 378 строк ядра, и 20 файлов прибиты к тексту исходников экранов. Любая переделка интерфейса = правка десятков тестов («страховка» превратилась в тормоз итераций).
3. **Церемония на каждый экран.** 15 экранов зафиксированы одновременно в ТЗ (`docs/15`), макете (`docs/16`), прототипе (`mockup/app.js`), реестре `nav.py`, глоссарии и тестах (`test_nav`, `test_target_docs`, `test_glossary`). Новый/переименованный экран — правки в 6–7 местах.
4. **Ядро и каталог шире MVP.** Для минимальной версии нужны ~12–15 операций контракта из 40 и ~30 проверок из 69 (остальное — T6–T11: модели, обучение, инференс, AutoML).
5. **Три источника истины по UI** (`docs/12` 200 КБ на старый UI, `docs/15+16` 190 КБ на целевой, `mockup/`) плюс гейты на каждый шаг.

**Что не утяжеляет и что надо сохранить:** Python-ядро и его тесты (сессия, наборы, программа, очередь, `runner`, `results`, `notes`, `report`, `dataset_composition`, `tasks_monitor`, `http_log`/`exchange`), реестр операций с классами безопасности (`endpoints.py` + `gen_endpoints`), `mockup/` как эталон макета.

## Архитектурные варианты

| Вариант                                                   | Суть                                                         | Плюсы                                                        | Минусы                                                       |
| --------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **A. Облегчить Streamlit**                                | 15 экранов → 6–8 (Планирование, Прогон, Результаты, Данные, Задачи, Сервис), автосборка очереди, карточка проверки — раскрытием внутри прогона, тесты «на подписи» удалить | минимум работы, ядро и тесты живут, MVP за считанные дни     | rerun-модель и написание UI на Python остаются; свободные приёмы макета по-прежнему недостижимы; «неочевидность» лечится не до конца |
| **B. Тонкий HTTP-API + статический UI на базе `mockup/`** | Бэкенд — stdlib `http.server` (`ThreadingHTTPServer`), отдаёт JSON **view-модели** (готовые строки таблиц, подписи статусов) поверх существующего ядра; фронт — `index.html`+`app.js`+`styles.css` из `mockup/`, где `demo-data.js` заменён на `fetch` | вся логика остаётся в протестированном Python, JS — только отрисовка; UI свободный и лёгкий (≈2 000 строк JS вместо 6 900 строк Python); старт одной командой без Streamlit; лента, `curl`, повтор с правками, редактор набора, фильтры — нативно; экраны не диктуются порядком `st.rerun` | два языка (Python-ядро + JS-обёртка); новые риски: экранирование данных стенда (`mockup/app.js` сейчас пишет через `innerHTML` **без escape** — надо закрыть), долгие операции (`fill`, `train`, инференс) требуют фонового потока + опроса статуса; JS-тесты минимальны (контракт API тестируется в Python) |
| **C. Гибрид**                                             | Python-API + JS-UI для прогона, Streamlit для отчёта/просмотров | переиспользование готовых экранов отчёта                     | двойная цена поддержки двух UI — не рекомендую               |

**Рекомендация: B, но инкрементально** (без повторения «big bang» — рабочее приложение на каждом шаге):
**Шаг 0** — зафиксировать юзкейсы, границы MVP, правило «логика в Python, JS только рисует» (этот документ).
**Шаг 1** — `acceptance/server.py`: ~12 JSON-эндпоинтов (`session/*`, `stand/snapshot`, `sets/*`, `programme/*`, `queue/build`, `run/next`, `results/protocol`, `report/*`, `dataset/composition`, `tasks/*`) + тесты JSON-контракта в Python; Streamlit пока работает как есть.
**Шаг 2** — `acceptance/web/` на базе `mockup/` (mockup остаётся замороженным эталоном): 15 M0-юзкейсов на живом API, `run_pult.bat` → `python -m acceptance.server` + открытие браузера.
**Шаг 3** — перенос M1 (лента+`curl`+повтор, замечания, данные стенда, `$Задачи`, снимок «Окончание», уборка `__TEST__`), плюс новый источник состава датасета `server_task`.
**Шаг 4** — вывод Streamlit-экранов и тестов «на подписи» из эксплуатации, `docs/12` → `docs/18` (инструкция под новый UI).
**Критерий MVP:** живой вертикальный срез «сессия → снимок „Начало“ → набор → программа → очередь → «▶ Следующая» → протокол → комплект отчёта и решение», плюс чтение состава существующего датасета, каждый шаг ≤ 3 действия.
