# Рамка К2 (уточнённая)

* вход — **боевой датасет**, загруженный оператором (внешне валидированный);
* модель выбирается **конкретная**, по свойствам, а не «первая с реестра»;
* параметры обучения и ресурсы — не экономим, качество важнее;
* выход — `.onnx` + метрики + комплект доказательств; всё фиксируется в сессии и отчёте.

# План Э1. «Карточка модели и свойства» (вкладка «Реальная тренировка»)

**Цель:** убрать «смотреть свойства модели в ленте» и дать выбрать **конкретную** модель осознанно.

## 1. Что показывает карточка (данные уже отдаются стендом — `ModelMetadata`)

| Блок                         | Содержимое                                                   |
| ---------------------------- | ------------------------------------------------------------ |
| Идентификация                | `id`, `name`, `description`, `architecture`, `version`, `phase_type`, `output_size`, «создана/обновлена» |
| Сигналы                      | группы `signal_num → device_ids[]` с `device_info` (нагрузка, категория), `signal_aliases` = классы (`{"0": "miner", "1": "not_miner"}`) |
| Конфигурация                 | `config.input_shape`, список слоёв (`layer_type` + параметры), `compile_config.loss`, `memory_management` |
| Обучение (из `metrics`)      | `epochs`, `batch_size`, `learning_rate`, `preprocessing_converter`, `augmentation_enabled`, `use_streaming`, `memory_usage`, `original_model_id`, `dataset_id` + `dataset_stats`, `training_history`, `testing_history` |
| Файл модели                  | `file_id` + имя/размер `.h5` из реестра файлов (если найден) |
| Производные (считает сервер) | «обучена: да/нет» (`metrics` не пуст), число групп сигналов/классов, «базовая/результат обучения» (`original_model_id`) |

Решение по производительности: `metrics` бывает крупным, поэтому **в таблице — компактно** («обучена», эпохи, ключевая метрика, размер файла), а **полная карточка — по запросу `GET /api/models/{model_id}`**.

## 3. Поведение в живых условиях (учтено из приёмок)

* `GET /api/models/{model_id}` — одиночное обращение, безопасно (read-only);
* фильтр `device_id` на стенде **падает 500** (дефект P1, `TC-MOD-05`) → пульт фильтрует по группам сигналов **локально**, в подсказке пишем причину;
* вкладка «Реальная тренировка» на Э1 показывает только блок «Модель», а шаги «Данные», «Обучение», «ONNX», «Комплект» — честные заглушки с пометкой «этап Э2/Э3/Э4», чтобы интерфейс не выглядел сломанным.

## 4. Гейты Э1

`pytest` · `tests/smoke` · `ruff check .` · `ruff format --check .` · `mypy acceptance pult tests client` · `python -m tools.gen_endpoints --check` (без изменений) · `node --check pult/web/*.js` · smoke-срез с карточкой · **браузерная приёмка** `chrome --headless=new --dump-dom http://127.0.0.1:<свободный порт>/#train` (в DOM должны быть свойства из `GET /api/models/{id}`) · **живая read-only проверка** карточки на реальной модели (`stft_mlp-skfu-train-dev (trained)`: видны группы сигналов, классы, метрики).

## 5. Объём и риски

* объём: ~8–10 файлов, ~400–600 строк с тестами — один этап, один коммит;
* риски и как снимаем: крупный `metrics` (карточка по запросу), дефект P1 (локальные фильтры), сессия v9 (терпимое чтение, старые сессии не падают), пустая вкладка (заглушки с планом).
