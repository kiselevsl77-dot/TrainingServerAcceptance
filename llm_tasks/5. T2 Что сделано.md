## Что сделано

**1. Реестр эндпоинтов — из спецификации, без ручных правок**
- `acceptance/endpoints.py` — 32 операции 6 модулей: метод, путь, параметры (типы/`enum`/значения по умолчанию), тело, вид ответа, **класс безопасности**, примечания об известных дефектах.
- `tools/gen_endpoints.py` — генератор: `--check` (сверка со спекой для CI), `--report`, автоформатирование; реестр правится только генератором.
- Классы назначены правилами: `DELETE` → `destructive`, `POST/PUT/PATCH` → `write`, `fill/train/check/async-инференс` → `heavy`, исключения объявлены явно (`tasks/test` → `write`, `inference/single` → `read`).

**2. Движок консоли (`acceptance/exchange.py`)** — «сырой» httpx с **тем же** `LoggingTransport`: исключений не бросает (сеть/404/422/5xx/некорректный URL → поля результата), тело читается с подбором кодировки `utf-8 → cp1251 → latin-1` (дефект `latin-1` виден как текст), тела обрезаются по `PULT_BODY_LIMIT`, файлы не удерживаются в памяти.

**3. Подтверждения ровно по решению (NFR-T4)** — `read`: без подтверждений, но **файл > 50 МБ требует подтверждения** (как в T1), размер/имя берутся из реестра; `write`: чекбокс + префикс `__TEST__` в именах (`name`, `title`, **`category`**, файл multipart); `destructive`: чекбокс + слово `DELETE`, **ввод `id` только если сущность не `__TEST__`** (имя уточняется по реестру, иначе — требуется `id`); `heavy`: карточка запуска из общего `run_card.py`, **`task_id` из ответа регистрируется в сессии** для монитора задач T4. Повтор разрешён только для чтения.

**4. Экраны** — «📡 Консоль запросов» (операция → параметры → подтверждения → результат со статусом/заголовками/телом/длительностью/номером журнала; действия «в артефакты / к проверке / замечание / повтор / очистить»; вкладки «История вызовов» и «Операции API») и «✍️ Замечания к API» (KPI, фильтры, карточка, правка/удаление, 11 шаблонов, перспективные требования, выгрузки md/csv/json). Общий хелпер `api_notes` — единая точка создания/дедупликации замечаний, экран «Записи» переведён на него.

**5. Сессия — schema v3**: `console_calls[]` (+`task_id`), `add_console_call`, `console_calls_by_label/summary`; события `console_call`, `console_task_started`, `console_attachment`; v1/v2 читаются как раньше.
