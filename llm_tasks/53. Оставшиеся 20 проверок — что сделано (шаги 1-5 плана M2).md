# 53. Оставшиеся 20 проверок: что сделано (шаги 1–5 плана M2)

Отчёт по `llm_tasks/52` («Уточнённый план 20 сценариев + фоновый слой + реальное
обучение»). Выполнены шаги 1–5 плана; шаг 6 (живой прогон обучения и приёмка в браузере)
описан в конце как оставшаяся работа с готовыми командами.

## Что появилось

### Клиент и подбор данных (шаг 1)

* `client/models.py` — полный модуль ML: каталог архитектур, создание модели, загрузка
  `.h5` (`metadata` строкой JSON + часть multipart), список с фильтрами, карточка,
  удаление, экспорт ONNX, `train`, `check`, `inference`, `inference/single`;
* `acceptance/ml_samples.py` — подбор модели/датасета и разбор строки RAW: только
  ASCII-имена (обход дефекта P0), канонический заголовок `RAW_COLUMNS`, `raw_row`,
  `RawSample` с доказательствами без Base64;
* на `RAW_COLUMNS` пересобрано тело кругового рейса `TC-FILE-13`: стенд проверяет состав
  колонок и отклонял «минимальный» CSV (найдено при живом прогоне).

### Сценарии 20 проверок T6–T9

| Проверка | Сценарий | Что делает |
|---|---|---|
| TC-MOD-01 | `models.architectures` | каталог архитектур и состав полей |

| TC-INF-01 | `inference.start` | задача `inference` — монитором, результат связан с проверкой диапазоном журнала |
| TC-INF-02 | `inference.single` | предсказ сэмпла из RAW: `classes[]` и границы `confidence` |
| TC-INF-03 | `inference.threshold_bounds` | 0.0/1.0 допустимы, вне диапазона — ошибка |

| TC-CLEAN-01 | `cleanup.self_cleaning` | уборка незакрытых сущностей по типам, проверка реестров, примечание о чужих следах |
| TC-CLEAN-02 | `cleanup.entities` | полнота перечня `__TEST__`-сущностей (вход в отчёт) |
| TC-CLEAN-03 | `cleanup.snapshots` | сверка снимков «Начало»/«Окончание»: дельта объясняется сущностями, расхождения — замечанием |

Все 20 проверок больше не «висят» без сценария: `automation=` заполнен у каждой,
`runner.automation_names()` — 66 (65 проверок + вспомогательное наблюдение `TC-TASK-08`).

### Фоновый слой пульта (шаг 4)

* `pult/jobs.py` — фоновые прогоны: одно активное задание (второй прогон отклоняется),
  история, статус, длительность, вердикт, диапазон журнала; ошибка задания не роняет пульт;
* `POST /api/run` с `background: true`, `GET /api/jobs`, `GET /api/jobs/{job_id}`;
* вкладка «Задачи»: фоновые прогоны, наблюдение за задачами (команды FSM-1, опрос,
  снятие наблюдения, постановка внешней задачи) и список задач стенда с честным
  источником статуса («опрос» / «нет данных»);
* параметры ресурсоёмких проверок (`epochs`, `batch_size`, `learning_rate`, `threshold`,
  `sample_file_id`, `keep_artifact`) — в карточке запуска и в подстановке тела вызова
  (`ML_OVERRIDES`), длинные значения маскируются (`mask_params`).
