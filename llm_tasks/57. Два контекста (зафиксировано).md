# 3. Целевой сценарий К2 (как это должно работать)

Один экран-мастер «ML-прогон» (сервер отдаёт готовые view-модели, JS только рисует — правило проекта):

1. **Профиль прогона.** Объект испытаний, цель, ответственный, целевые метрики, режим «полная нагрузка» → двойное подтверждение (галочка + слово, как требует `docs/12` §24.1 для `destructive`). Профиль пишется в сессию (`ml_profile`).
2. **Данные.** Загрузка файлов (в т.ч. пакетом: список путей/папка на диске пульта → очередь загрузки), создание датасета, `fill`, ожидание задачи `dataset-fill`, затем **паспорт датасета**: N файлов, суммарный размер, `sha256` каждого, число записей/чанков, дата и автор → кнопка «Датасет проверен». Для боевого датасета — явное подтверждение «это боевые данные».
3. **Модель.** Реестр с фильтрами + **карточка**: архитектура, `phase_type`, `output_size`, группы `signals` (какие устройства), `signal_aliases` (классы), `config` (слои), `metrics`, `file_id`/размер `.h5`, `original_model_id`, `updated_at`. Действия: «выбрать для прогона», «обучить», «экспорт ONNX», «скачать ONNX», «удалить».
4. **Обучение.** Параметры: `dataset_id`, `model_id`, `epochs`, `batch_size`, `learning_rate`, `preprocessing_converter`, `augmentation_noise_percentage`/`num_samples`, `quantization`, `trained_model_name`; запуск фоновой задачей (`pult/jobs.py`) + наблюдение FSM-1 в «Задачах»; журнал шага.
5. **Метрики.** Экран результата: карточка обученной модели + сравнение с базовой (до/после) по `training_history`/`testing_history`/`dataset_stats`; «принять показатели качества» → в сессию и в отчёт.
6. **ONNX.** «Экспорт и скачать»: конвертация стендом, проверка (размер > 0, маркер `onnx`, имя `*.onnx`, `sha256`), запись артефакта в сессию, отдача файла браузеру.
7. **Комплект.** «Собрать комплект»: папка с `.onnx`, `metrics.json`, `dataset_manifest.json`, `run_card.json`, сводкой проверок + zip; запись в артефакты и в отчёт (раздел 8).

# 5. Этапы (предложение порядка)

| Этап   | Что                                                          | Почему в этом порядке                                        | Приёмка этапа                                                |
| ------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **Э1** | Карточка модели и свойства + выбор «конкретной» модели       | Самое дешёвое и самое нужное: убирает «смотреть свойства модели в ленте» | карточка показывает `signals`/`signal_aliases`/`config`/`metrics`; выбор модели для прогона сохраняется |

| **Э3** | Обучение: полный набор параметров, прогресс, метрики до/после, запись в сессию | Даёт «реальные результаты»                                   | задача FSM-1, метрики в сессии/отчёте                        |
| **Э4** | ONNX: экспорт, скачивание оператору, проверка целостности, комплект | Замыкает сквозной результат                                  | файл `.onnx` + `metrics.json` + `dataset_manifest.json` в комплекте |

Э1–Э2 можно делать параллельно с подготовкой боевого датасета у заказчика.
