# 68. «Реальная тренировка»: загрузка файлов — роль «авто», проверка формата, выбор файлов стенда

Продолжение `llm_tasks/67` (там зафиксирован симптом — `[502] CSV header is missing required
columns: …`). Здесь — правки по четырём замечаниям оператора к зоне «Данные (датасет)».

## 0. Что было не так (замечания оператора)

1. В разделе загрузки **одна выпадашка роли на всю «пачку»** (`train-upload-role`): чтобы
   загрузить измерения и разметку, приходилось делать два прохода, и пары файлов «теряли»
   соседство. Комфортнее — выбрать все файлы сразу, а роль определить по файлу.
2. Смешанная загрузка давала стендовый отказ
   `[502] CSV header is missing required columns: i_c_signal, …` (build 30.09.2026):
   markup-файл уходил с ролью `RAW` и стенд валидировал его как raw_data.
3. Не все файлы датасетов заведомо соответствуют формату — нужна **проверка формата raw/markup
   при загрузке**, а не постфактум на стенде.
4. В интерфейсе нельзя было **выбрать файлы стенда** (уже лежащие в реестре) для наполнения
   датасета: кнопка «↻ Файлы стенда» лишь перечитывала реестр, `fill` брал только файлы,
   загруженные в текущей сессии.

## 1. Что сделано

| Файл | Что сделано |
|---|---|
| `pult/datafile_format.py` (новый, чистый) | `HeaderRecorder` (снимает первые байты потока «на лету»), `first_line`, `parse_header` (`;`, при отсутствии — `,`), `detect_role` (RAW по сигналам, LOADS по `markupId`/`LoadID`/`Ph_n`), `missing_columns`, `RAW_REQUIRED` (22 колонки из `acceptance.ml_samples.RAW_COLUMNS` без `chunkID`/`timestamp`), `LOADS_REQUIRED` (`markupId;chunkID;LoadID;Ph_n;Category`) |
| `pult/models.py` | `FILE_ROLES` дополнен режимом `AUTO` («авто (по заголовку)»); новый `registry_rows` — файлы реестра стенда для выбора в датасет |
| `pult/server.py` | `api_data_upload`: заголовок снимается во время потоковой записи, роль резолвится (`_resolve_role`), формат проверяется **до** отправки на стенд (422 с перечнем колонок вместо 502); `_train_view` кладёт `data.registry`; `_manifest_files` не теряет файлы, выбранные из реестра; `fill` уже принимал явные `raw_file_ids`/`markup_file_ids` |
| `pult/view.py` | `train_view` отдаёт `data.registry` (RAW/LOADS) для выбора; реестр материализуется один раз |
| `pult/uploads.py` | первый параметр `save_stream` — протокол `ReadableStream` (подходит и `rfile`, и обёртка заголовка) |
| `pult/web/index.html`, `app.js` | выбор роли «авто»; **пофайловые** итоги загрузки (роль по факту, отказ с причиной; один сбой не прерывает пачку); блок «Файлы стенда для датасета» с выбором RAW/LOADS; «⇪ Наполнить файлами» отправляет выбранные `id` |

### Как это отвечает на замечания

1. Роль `AUTO` определяется по заголовку каждого файла — смешанную «пачку» грузим одним проходом.
2. Формат проверяется на пульте; markup под ролью `RAW` получает понятное «нет обязательных
   колонок: …» **до** стенда (без 502 и без заливки гигабайтов).
3. Проверка формата raw/markup обязательна для всех загрузок: несоответствие — отказ с именами
   колонок; неопознанный формат при `AUTO` — отдельное сообщение.
4. Файлы, уже лежащие на стенде, выбираются в блоке «Файлы стенда для датасета» и уходят в
   `fill` как `raw_file_ids`/`markup_file_ids`; паспорт сборки их сохраняет.

## 2. Границы (честно)

* правила имён §9 не менялись: вне режима полной нагрузки имена начинаются с `__TEST__`;
* роль `AUTO` резолвится в роль стенда (`RAW`/`LOADS`) до записи паспорта — «AUTO» в хранилище
  и в паспорте не попадает;
* предпросмотр разметки (записи/чанки) и её достоверность — по-прежнему ответственность
  оператора вне стенда (решение заказчика №6).
