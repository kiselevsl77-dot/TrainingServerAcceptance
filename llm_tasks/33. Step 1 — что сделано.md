## 3. Что именно сделано

### 3.1 Ядро (изменения, которые видит пользователь)

* **Очередь прогона не хранится.** Состав прогона восстанавливается по номеру ревизии
  (`run_state.run_queue` → `queue.queue_for_revision(programme, revision)`), а состояние
  пунктов — по единственному следу результата (`results.py`). Значит, «очередь» больше
  не может разойтись с программой: правка состава программы не создаёт «зависших» пунктов.
* **«Выполнено по факту запроса».** Пункт закрывается без запуска, если в журнале **этой
  сессии** есть успешный ответ 2xx по каждому эндпоинту проверки (`run_state.confirm_by_request`).
  Запись идемпотентна, в протоколе видно способ: «запрос сессии» и пометка
  «выполнено по факту запроса». Приоритет — журналу этой сессии, затем `results.py`.
* **Режим «только невыполненное»** — `session.skip_done` (по умолчанию включён).
* **Состав датасета** читается через задачу наполнения: `GET /api/tasks/?task_type=dataset-fill`
  → задача → `parameters`/`result`; приоритет источника `сервер → задача → факт пульта →
  оценка → неизвестно` (`dataset_composition.py`).

### 3.2 Сервер пульта (`pult/server.py`, 20 маршрутов §4 ТЗ)

Шапка и сессии: `GET /api/state`, `GET|POST /api/sessions` (создание и выбор),
`POST /api/sessions/{id}/start|snapshot|finish`.
Планирование: `GET|POST /api/catalog`, `GET|POST /api/sets`, `GET|POST /api/programme`.
Испытания: `GET|POST /api/run` (`next|batch-tech|call`), `POST /api/checks/{id}`
(`annotate|suspend|resume|run-card`).
Наблюдение и результаты: `GET|POST /api/journal`, `GET /api/protocol` (+`?format=csv`),
`GET /api/data`, `GET /api/report/readiness`, `POST /api/report/build`.

Решения, заложенные в контракт:

* единый конверт `{ok, data}` / `{ok, error: {kind, message, exchange_seq}}`;
* «нет сессии» и «стенд не задан» — понятные ошибки с кодом (`409`), а не пустые таблицы;
* статика отдаётся с проверкой пути (`pult/web` — граница, выход запрещён);
* тяжёлые действия держат замок `run_lock`: двойной клик по «▶ Следующая» не отправляет
  проверку дважды, второй запрос получает «прогон уже идёт»;
* `GET /api/run` закрывает пункты, уже подтверждённые запросами сессии (идемпотентно);
* тела запроса/ответа в ленте включаются **независимо** (`request=0/1`, `response=0/1`),
  каждая запись несёт готовую команду `curl` (`FR-P-21`…`FR-P-23`).

### 3.3 Страница (`pult/web/**`)

`index.html` + `app.js` + `styles.css`, без сборки и без библиотек. Панели:

| Панель | Что можно сделать сейчас |
|---|---|
| Шапка | видно стенд и сборку, сессию, ревизию и статус программы, фазу Ф0–Ф4, прогресс, «▶ Следующая: `TC-…`» (или причину, почему нельзя), предупреждения (расхождение сборок, замечания программы) |
| Прогон | строки прогона с маркером, состоянием, результатом, способом получения и диапазоном журнала; кнопки «▶ Следующая», «▶▶ Пачка tech», «снять/вернуть» пункт с причиной; итоги последнего запуска |
| Сессии | список сессий, выбор, создание по реквизитам, «старт» (снимок «Начало») и «завершить» |
| Протокол | KPI (успех/отказ/блокировано/пропущено/вручную/не выполнено/повторов/снято), таблица с «вне программы», выгрузка CSV |

## 7. Как проверить руками (5 минут)

1. `.\run_pult.bat` (или `python -m pult.server --browser`) — откроется `http://127.0.0.1:8502`.
2. Панель «Сессии» → заполнить «Наименование» и «Объект испытаний» → «Создать сессию» →
   в строке сессии «старт» (снимок «Начало», в шапке появится сборка стенда).
3. «Протокол» → KPI пустые: программа ещё не собрана.
4. Собрать программу можно уже сейчас через API (страница появится в Step 2), например
   в PowerShell:
   ```powershell
   $sets = (Invoke-RestMethod http://127.0.0.1:8502/api/sets).data.rows
   Invoke-RestMethod http://127.0.0.1:8502/api/programme -Method Post -ContentType 'application/json' `
     -Body (@{action='rebuild'; set_ids=@($sets[0].set_id)} | ConvertTo-Json -Depth 4)
   Invoke-RestMethod http://127.0.0.1:8502/api/programme -Method Post -ContentType 'application/json' `
     -Body (@{action='approve'; comment='проверка вручную'} | ConvertTo-Json -Depth 4)
   ```
5. Панель «Прогон» → «▶ Следующая» (пункт выполнится, появится строка итога) →
   «Протокол» покажет результат, диапазон журнала и выгрузку CSV; «Лента обмена» — тела и `curl`.

## 10. Дефект, найденный при первом запуске (25.09.2026), и его исправление

### Что было видно

При запуске `run_pult.bat` браузер **скачивал** `index.html` вместо того, чтобы открыть
страницу: ни стилей, ни работающих кнопок. Вопрос заказчика: «Это именно тот итог, который
стоило ожидать?» — нет, это дефект реализации, а не задуманное поведение.

### Причина

`pult/server.py`: статика отдавалась тем же типом ответа, что и скачиваемые файлы, и
`filename` заполнялся всегда —

```python
return Raw(candidate.read_text(...), content_type=mime, filename=candidate.name)
```

а `_ok()` на непустой `filename` безусловно ставил `Content-Disposition: attachment`.
Следствие: `index.html` уходил как вложение (браузер его сохранял), а `styles.css` и
`app.js` — тоже вложением, поэтому стили не применялись и скрипт не выполнялся.

### Почему не поймали гейты

Тесты проверяли тело и `content_type` объекта `Raw`, но **не заголовки** живого ответа;
`Invoke-WebRequest` читает и «вложенный» ответ, поэтому ручная проверка выглядела зелёной.
Браузера в проверках не было вовсе.

### Что исправлено

* `Raw` теперь несёт **байты** (`data: bytes`), тип содержимого, имя файла и признак
  `download`; `Content-Disposition: attachment` ставится **только** при `download=True`
  (CSV протокола), статика отдаётся для отображения;
* `static()` читает файл `read_bytes()` — иконки, PNG и шрифты больше не «падают» на чтении
  текста; добавлен `Cache-Control: no-store`, чтобы правка JS не залипала в кэше браузера;
* новые проверки: `test_static_is_served_for_rendering_not_download` (живой HTTP: у `/`,
  `/app.js`, `/styles.css` нет `Content-Disposition` и верные типы),
  `test_protocol_csv_is_served_as_attachment` (выгрузка осталась файлом),
  `test_static_reads_binary_files_as_bytes`; смоук-срез дополнительно проверяет, что
  страница не отдаётся вложением;
* **ручная проверка отрисовки браузером** внесена в гейты (`.clinerules`, README):
  `chrome --headless=new --dump-dom http://127.0.0.1:8502/` — так ловятся и «вложение»,
  и «скрипт не выполнился».
