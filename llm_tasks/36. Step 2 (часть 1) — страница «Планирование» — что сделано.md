# Step 2, часть 1 — страница «Планирование» (UC-05, UC-06)

Ветка `webui`. Дата: 25.09.2026. Продолжение `llm_tasks/33` (Step 1) и `llm_tasks/35`
(план этой части). Коммиты: `14a31de` (API планирования) и страница — следующим коммитом.

## 1. Итог одной строкой

На пульте появилась вкладка **«Планирование»**: слева каталог проверок с фильтрами и
массовым выбором, в середине библиотека наборов с составом и ревизиями, справа программа
сессии с покрытием разделов, предупреждениями, обоснованием сокращения, ревизиями и
дельтой. Всё, что считает сервер, приходит странице готовыми view-моделями — в JS
по-прежнему нет ни подписей, ни расчётов.

## 2. Коммит A — API, которого не хватало (UC-05)

Ядро умело больше, чем отдавало API: без этих действий нельзя было ни убрать проверку из
набора, ни задать порядок, ни выпустить ревизию набора.

| Маршрут | Было | Стало |
|---|---|---|
| `POST /api/sets` | `save|approve|delete|import` | + `remove|reorder|move|mandatory|revise|restore` |
| `POST /api/programme` | `rebuild|approve|revise|restore` | + `reorder|move|mandatory` |

Поведение:

* правка утверждённого набора/ревизии по-прежнему запрещена (`FR-P-66`, `FR-P-13`):
  `ValueError` ядра превращается в `409` с текстом «изменение возможно только новой
  ревизией» — оператор видит правило, а не «ошибку сервера»;
* неизвестное действие — `422`, отсутствующий набор или пункт — `404`;
* «полусырой» JSON из браузера не роняет сервер: `check_ids`, сдвиг `delta` и номер
  `revision` разбираются помощниками (`_check_list`/`_delta`/`_revision`);
* тело действий программы теперь тоже обёрнуто разбором ошибок ядра — раньше часть ошибок
  уходила как `500`.

ТЗ `llm_tasks/31.4` §4 (строки 8 и 10) приведено к фактическому списку действий.

## 3. Коммит B — страница

| Зона | Что видно и что можно сделать |
|---|---|
| **Каталог проверок** | фильтры «поиск / раздел / класс» (фильтрует сервер), таблица (проверка, название, класс, раздел, требование, метки «в наборе»/«в программе», статус сессии), галочки массового выбора, «обязательные (смоук-минимум)», «Добавить в набор», «Создать из выбранных» |
| **Библиотека наборов** | статус (✅/✎), ревизия, число проверок и обязательных, участие в программе, пересечение; действия «состав», «утвердить»/«ревизия», «удалить» (утверждённый — с подтверждением); отдельный список состава: порядок, названия проверок, обязательность, ↑/↓, «✕» |
| **Программа сессии** | KPI (пунктов, обязательных, наборов, разделов, не покрыто, пересечений, вне каталога), галочки наборов-участников и «Пересобрать программу», предупреждения, обоснование сокращения, «Утвердить ревизию» / «Новая ревизия», покрытие разделов (в программе / реализовано / план / цель / не хватает), история ревизий с «вернуть», дельта с предыдущей (+/−), пункты программы с ↑/↓ и флагом «обязательная» |

Новое в сервере и view-моделях:

* `GET /api/catalog` отдаёт `classes` — справочник классов для фильтра
  (`view.class_options()`), чтобы браузер не дублировал подписи у себя;
* `view.sets_rows` отдаёт `items` — состав набора строками с названием и классом проверки
  (`view._set_item_rows`), поэтому странице не нужны «склейки» по идентификаторам.

Интерфейс:

* вкладки стали: **Прогон · Планирование · Сессии · Протокол · Лента обмена**;
* маршрутизация по адресу: `#planning`, `#run`, … — вкладку можно открыть ссылкой (и так её
  отрисовку проверяет headless-браузер);
* KPI-плитки вынесены в общий помощник `fillKpi` («Протокол» и «Программа»);
* длинные таблицы прокручиваются внутри зоны (`.grid--scroll`), шапка страницы остаётся на
  месте; всё рисуется через `textContent` — данные стенда не попадают в `innerHTML`.

процессы сняты; фиксирую здесь, чтобы такой «фантом» не приняли за дефект страницы.

## 6. Как проверить руками

1. `.\run_pult.bat` → `http://127.0.0.1:8502/#planning` (или вкладка «Планирование»).
2. «Сессии» → создать и стартовать сессию (без неё страница честно пишет «программу
   собирать не в чем»).
3. «Планирование»: отметить проверки в каталоге (или «выбрать все»), выбрать набор и
   «Добавить в набор», либо «Создать из выбранных».
4. В «Библиотеке наборов» нажать «состав» у своего набора, при необходимости снять/поставить
   «обязательную», сдвинуть порядок, «утвердить».
5. В «Программе сессии» отметить наборы, «Пересобрать программу», заполнить «обоснование
   сокращения» (его требует утверждение при непокрытых разделах) и «Утвердить ревизию».
6. Ошибки видны всплывающей плашкой с кодом: `409` — «набор утверждён: изменение только
   новой ревизией», `422` — «не выбран ни один набор», `404` — «пункта нет в программе».
