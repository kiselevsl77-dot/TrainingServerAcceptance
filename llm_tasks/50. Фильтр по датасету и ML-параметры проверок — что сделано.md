# Фильтр данных по датасету и ML-параметры проверок — что сделано

**Итог:** четыре пункта плана (`llm_tasks/49`, решения заказчика по `llm_tasks/48`) сделаны,
гейты зелёные, а живая проверка (только чтение живого стенда) нашла и закрыла **два дефекта**,
которые HTTP-тесты не видели: страница «Прогон» показывалась вместо «Планирования»
(дубль `id="panel-planning"`), а фильтр по датасету присоединял к нему чужие файлы-тёзки
(312 строк вместо 104).

## Что сделано по пунктам плана

### 1. Согласованный порядок вкладок и старт на «Планировании» (`3db779e`)

* порядок вкладок: **Планирование, Сессии, Прогон, Результаты, Лента обмена**;
* `is-active` стоит на `panel-planning` (как и просил заказчик: работа начинается с плана);
* список панелей вынесен в `PANELS` (`app.js`), `panelFromHash` по умолчанию открывает
  `PANELS[0]`, неизвестный адрес — тоже стартовую вкладку, а не «Прогон»;
* страж `test_tab_order_matches_agreed_sequence`: разметка вкладок, активная панель и
  список `PANELS` в JS обязаны совпадать.

### 2. «Данные стенда»: сворачиваемые подразделы, счётчики, `$Модели` (`10aa624`)

* пять подразделов `<details class="zone__sub">` — свёрнуты по умолчанию, состояние
  сворачивания не сбрасывается автообновлением (живёт в DOM);
* счётчики считает Python (`view.data_sections`): `$Файлы · 388`, `Записи RAW + markup · 207`,
  `$Нагрузки · 62`, `$Датасеты и состав · 7`, `$Модели · 19`;
* `$Модели` — новый подраздел (`PultState.models()` → `ModelMetadata`, TTL 30 с), со
  подписью «имя · архитектура · версия · фаза»;
* лимит строк и честный счётчик: по умолчанию 200 строк и подпись «показано 200 из 388»,
  `?limit=0` — весь реестр; нечисловой `limit` → `422` (раньше список обрезался молча).

### 3. Фильтр RAW/markup по датасету (`f8e9a2e`, `ba26ab6`)

* `?dataset=<id>|none` + `?source=auto|server|server_task|local|heuristic` для
  `GET /api/results`/`GET /api/data`: `$Файлы` и `Записи RAW + markup` показывают **только**
  файлы состава, подпись подраздела — `$Файлы · 104 из 388` (видно и выборку, и реестр);
* `dataset=none` — режим «файлы вне датасетов»: остаётся то, чего нет ни в одном составе
  (составы всех датасетов берутся из кэша 60 с, `PultState.composition_cache`);
* блок `filter` объясняет всё словами: режим, источник состава, достоверность, число
  файлов/RAW/markup, готовую подпись и `unavailable`-список. Состав недоступен или пуст →
  фильтр **не применяется**, и это сказано прямо: «фильтр не применён — состав недоступен
  (P1): показаны все файлы реестра» (`FR-P-25`);
* варианты селекта строит сервер: «весь реестр (388 файлов)», «файлы вне датасетов»,
  далее датасеты с составом, когда он уже прочитан;
* в интерфейсе: селект датасета, селект источника, «🔍 показать файлы и записи этого
  датасета», «сбросить фильтр» и подпись; выбранное переживает автообновление.

### 4. ML-проверки: датасет и модель в карточке и в параметрах (`97463ed`)

* ядро знает, что нужно проверке, **по спецификации**: `runner.ml_params_required` —
  `dataset_id` ищется в **теле** (`train`, `check`, `inference`), `{model_id}` — в **пути**.
  Каталог даёт 12 таких проверок: `TC-MOD-06/07`, `TC-TR-01/02/04/05/06`,
  `TC-INF-01/02/03/04`, `TC-CLEAN-01`;
* карточка запуска получила поля **«Датасет для проверки»** и **«Модель»** (селекты из
  реестров стенда), `run_card.validate(required_extra=…)` требует их только там, где
  проверка их использует, а `evidence` хранит и `id`, и подписи («skfu-train · файлов 104»);
* для проверок без карточки (`tech`) — панель **«Параметры проверки: данные и модель»**;
  выбор сохраняется через `POST /api/checks/{id}` `action=ml-params` (решение 2 = а) и
  уходит в `params` при запуске; в селекте есть «не выбрано», чтобы браузер не подставил
  молча первый датасет;
* `POST /api/run {action:"call"}` без выбранных данных отвечает `422` со списком полей —
  вместо отправки заглушки `"<uuid>"` на стенд;
* **подстановка**: `runner.substitute_placeholders` заменяет значения верхнего уровня вида
  `"<…>"` в теле вызова на выбранные параметры. Списки (`file_ids` в `fill`) и вложенные
  объекты (AutoML `range`) не трогаются, собственное тело оператора (`values["body"]`)
  по-прежнему главнее шаблона;
* предпросмотр payload больше не молчит про ML: у `train`/`check`/`inference` появилась
  строка «обучение модели: модель «skfu-net · cnn · v3» (`id`), датасет «skfu-train»
  (файлов 104)», а без выбора — «датасет не выбран: запуск не состоится».

  были `TC-SYS`): пульт не шумит лишними полями.

## Что осталось за рамками (осознанно)

* **AutoML**: в каталоге нет проверок на `find_params`/`population`, поэтому `train_dataset_id`
  правилом `ml_params_required` не ловится — разбор AutoML отдельным этапом (как и записано
  в решении заказчика).
* **Живой вызов `train` не отправлялся**: живая проверка стенда — только чтение. Подстановка
  датасета в тело и `model_id` в путь доказана сквозным тестом на подменённом стенде (запрос
  перехватывается и разбирается) плюс юнит-тестами `substitute_placeholders`.
* Тёзки-файлы при источнике `heuristic` попадают в состав — это честно и подписано
  «требует проверки»: гипотеза знает только имена, отличить копии ей нечем.
