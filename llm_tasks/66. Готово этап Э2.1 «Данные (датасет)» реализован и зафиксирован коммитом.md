## Готово: этап Э2.1 «Данные (датасет)» реализован и зафиксирован коммитом

**Коммит `c36751f` в ветке `webui`** (дерево чистое; в untracked остались только ваши файлы `llm_tasks/60–63`, `serv_docs/1.2`).

### Что теперь умеет пульт
| Действие                                         | Как это работает                                             |
| ------------------------------------------------ | ------------------------------------------------------------ |
| «⬆ Загрузить на стенд»                           | файл уходит на стенд **потоком** — тело запроса это сам файл, параметры в query-строке; браузер показывает прогресс, пульт считает размер и `sha256`, временный файл удаляется сразу после отправки |
| «Загружено в этой сессии»                        | таблица с ролью (измерения/разметка), размером, `sha256` и `file_id` стенда |
| «➕ Создать датасет»                              | `POST /api/datasets/` с именем `__TEST__…`; боевые имена — только при подтверждённом режиме полной нагрузки (§9 ТЗ) |
| «⇪ Наполнить файлами»                            | `fill` выбранными `file_id`; факт «что отправлено» фиксируется **до** вызова (стенд не отдаёт ни состав, ни `task_id`), задача `dataset-fill` ищется в `$Задачах` |
| «✔ Проверен вне пульта»                          | отметка + **паспорт сборки**: какие файлы, размеры, `sha256`, кто и когда собрал |
| «↻ Перечитать состав» / `GET /api/datasets/{id}` | состав по учёту пульта или запросом к стенду, паспорт и список файлов |

### Ключевое техническое решение
Разбор `multipart/form-data` **не делается намеренно**: оба конца наши, а боевой RAW доходит до **2,18 ГБ** — поэтому файл идёт сырым телом, а пульт пишет его на диск порциями по 1 МБ (память ограничена порцией). JSON-лимит 1 МБ не тронут — у загрузки свой лимит `MAX_UPLOAD` = 3 ГиБ (превышение → 413 **до** чтения тела).
