### Дополнительно исправлено: фильтры периода в списке задач

Оператор видел на вкладке «Список задач» ошибку **[422] Input should be a valid datetime…**
на каждом показе: экран отправлял «чистые» даты
(`GET /api/tasks/?start_date=2026-09-09&end_date=2026-09-16&limit=25`), а стенд разбирает
`start_date`/`end_date` как дату-время (`format: date-time` в спецификации). Причина
пропущена тестами: локальный `pydantic` такие строки принимает, сценарий TC-TASK-02 период
не проверял, а заглушка смоук-теста отвечала независимо от query.

* границы периода считает `lib.period.day_bounds`: начало — `<день>T00:00:00`, конец — начало
  следующих суток (граница `end_date` на сервере исключающая, `created_at < end_date`);
* период включается переключателем «Фильтр по периоду» (по умолчанию выключен — видны все
  задачи сервера), под фильтрами показаны фактические границы запроса;
* страховка в клиенте (`client/tasks._iso`) и заглушка смоук-теста, повторяющая поведение
  стенда (422 без `T`) — регрессия падает в тестах;
* TC-TASK-02 получил пробы периода и факт `date_only_probe = 422`; добавлен шаблон замечания
  P2 о семантике границ; `ParamSpec.format` из спецификации показывается в консоли как
  подсказка формата (`start_date (string, date-time)`);
* новые тесты: `tests/unit/test_period.py`, расширения `test_tasks_api.py`,
  `test_endpoints.py`, `test_console_page.py`, живая проба в `test_live_tasks.py`.

### Дополнено: статус в списке задач и смежные атрибуты

> **Заменено следующим разделом** («Дополнено: статусы, снимок и архив в списке задач»):
> колонка «Статус» теперь собирается из трёх источников и окрашена, кнопки

* замеры и следствия для отчёта: 10 карточек ≈ 7,4 с последовательно и ≈ 0,7 с через пульт

### Дополнено: статусы, снимок и архив в списке задач

Оператору нужен был список, по которому сразу видно, **что исполняется, а что давно
завершилось**: прежняя таблица показывала длинный `id`, полное название и описание,
а статус — только из наблюдения (то есть у незнакомой задачи его не было).

* **Статус строки** собирает `TaskMonitor.task_status_view` из трёх источников с
  приоритетом «карточка → снимок → последний опрос», а колонка **«Источник»** говорит,
  откуда он взят; если данных нет, в строке честное «— нет данных». Карточки видимых
  строк догружаются **батчами по 25** (внутри батча параллельно, 5 потоков) с меткой
  `TC-TASK-02` и прогрессом, и после батча страница перерисовывается — статусы появляются
  без действий оператора (кэш `STATUS_CACHE_TTL = 30` с, кнопка «⟳ Обновить статусы» его
  сбрасывает).
* **Снимок статусов и архив** — новый модуль `acceptance/task_snapshot.py`
  (`acceptance_data/task_snapshot.json`, общий для пульта, как `records_overrides.json`;
  схема сессии осталась v4 — протокол ведут журнал и чек-лист). Задача с терминальным
  статусом уходит в архив автоматически, когда завершена **более суток назад**
  (`ARCHIVE_AFTER`), а вернувшаяся в работу — из архива возвращается; кнопка
  «📦 Перенести завершённые в архив» делает то же по требованию оператора, с
  подтверждением и ценой действия (сначала опрос карточек задач с неизвестным статусом).
  Вид «📦 Архив» по умолчанию показывает завершённые ≥ суток назад, флажок добавляет
  «только что перенесённые». События `tasks_archived[_auto]`, `tasks_unarchived_auto`
  пишутся в журнал.
* **Компактная таблица**: `id` — последние 8 символов, название и описание — первые 21
  символ; полные значения — в панели строки (`st.code` с кнопкой копирования), флажок
  «Полные значения» отключает сокращение. Колонка «Статус» раскрашена (`pandas.Styler`:
  зелёный — исполняется/завершена, жёлтый — пауза, красный — ошибка, оранжевый — прервана,
  серый — нет данных), а легенда пиктограмм есть в подписи под таблицей.
* **Порядок и страницы — в пульте**: список читается целиком (`limit` стенда не ограничен,
  проверено `limit=1000`; пульт режет его на `LOAD_TASK_CAP = 500`) и сортируется по
  «создана ↓» (`created_at` + `id`), пагинация клиентская — на этом держатся виды
  «Активные / Архив / Все».
* **Сообщения оператора не теряются** при фоновых перерисовках: `repeat_flash`
  (`ui/common/flash.py`) возвращает показанный текст в очередь перед `st.rerun`.
* Проверки и пробы: `TC-TASK-02` получил факты `limit_uncapped`, `list_unsorted`,
  `archive_is_local`; новые тесты `tests/unit/test_task_snapshot.py`,
  `tests/unit/test_ui_labels.py`, расширения `test_tasks_monitor.py`,
  `test_checks_tasks.py`, smoke-сценарии архива и «нет данных», живые пробы «список
  целиком и не отсортирован» и «архива в API нет». Замечания по Task service дополнены
  фактами (нет времени завершения и признака архива, `limit` не ограничен) — шаблонов
  по-прежнему 14.

## Известные ограничения

* `POST /api/datasets/fill/{id}` не отдаёт `task_id` (P1): обходной путь `TaskMonitor.find_recent` (`GET /api/tasks/`) — полное решение в T5.
* Экран «Задачи» опрашивает задачи **по одному разу за перерисовку** (интервал из `PULT_POLL_INTERVAL`, настраивается по задаче); блокирующий `watch()` используется только в консоли и тестах.
* Чек-лист открыт только для группы `TC-TASK`; остальные группы появятся в T3 — каталог и движок переделывать не нужно.
