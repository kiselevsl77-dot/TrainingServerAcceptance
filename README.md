# Пульт испытаний сервера обучения Energomera

Временный (альтернативный) UI для **испытаний и приёмки текущей версии сервера
обучения** по OpenAPI-спецификации `SOM1.json` — без доработки API сервера.
Все действия выполняются прозрачно (каждый запрос виден и протоколируется),
а результат оформляется отчётом об испытаниях.

> Основной UI (`TrainingServerUI`) развивается по своему плану (FR-1…FR-8).
> Пульт — независимый проект: полная изоляция, собственная копия `client/` и
> `lib/`, см. `VENDOR.md`. Наработки пульта, полезные основному UI — `BACKPORT.md`.

## Что уже работает (этапы T0–T2)

| Экран | Состояние |
|---|---|
| 🖥️ **Стенд** | `/health` и `/version` (все поля сборки), параметры подключения, пути журналов, снимок реестров (файлы/нагрузки/модели/датасеты/задачи + записи: объединение, дубли, несопоставленные) на начало и окончание сессии, сравнение снимков |
| 🧪 **Сессия испытаний** | создание/старт/завершение/переоткрытие, поля сессии (наименование, программа-методика, объект, заказчик, организация, оператор, комиссия, цель, объём, условия, ограничения, критерии, подписи), история событий, артефакты испытаний, характеристики разметки, ручные вызовы консоли (`console_calls`), файл сессии (выгрузка/загрузка), список сессий |
| 🧩 **Записи (RAW + markup)** | объединение реестра в записи по явному правилу (имя + время импорта) с показом правила и уверенности, KPI (записи, покрытие, дубли, без разметки), карточки с обеими частями и кандидатами, вкладки «Дубли» / «Несопоставленные» / «Прочие файлы» / «Манифест», выгрузка RAW/markup/пары-zip (крупные — с подтверждением), разбор разметки (записи/чанки), ручные решения оператора (`link`/`unlink`/`exclude`/`current`), манифест объединения CSV/JSON и сохранение в артефакты сессии |
| 📡 **Консоль запросов** | все 32 операции 6 модулей из `SOM1.json` (реестр генерируется), шаблоны пути/query/JSON/multipart, классы безопасности и подтверждения (префикс `__TEST__`, слово `DELETE` + ввод `id`, карточка запуска), результат со статусом/заголовками/телом/длительностью/размером и номером записи журнала, действия «в артефакты / к проверке / замечание к API / повтор / очистить», вкладки «История вызовов» и «Операции API» |
| ✍️ **Замечания к API** | реестр замечаний с приоритетами P0/P1/P2: KPI, фильтры и поиск, карточка замечания, правка и удаление с подтверждением, 11 шаблонов известных дефектов, перспективные требования (бэклог), выгрузка Markdown/JSON/CSV и сохранение комплекта в артефакты сессии |
| 🧾 **Журнал** | все обмены с сервером (метод, путь, статус, мс, размеры, метка проверки), фильтры (ошибки/метка/подстрока), детали обмена, очистка, выгрузка JSON, скачивание JSONL сессии, хвост `app.log` |
| ✅ Чек-лист · 📄 Отчёт | заглушки (этапы T3, T9, см. «Этапы») |

## Настройка и запуск

```powershell
.\run_pult.bat        # Windows: создаст .venv, поставит зависимости, откроет http://localhost:8502
./run_pult.sh         # Linux/macOS
```

Переменные окружения (`.env`, шаблон — `.env.example`):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TRAINING_SERVER_BASE_URL` | адрес испытуемого сервера (обязательно) | — |
| `TRAINING_SERVER_TIMEOUT` | таймаут обычных запросов, с | 15 |
| `TRAINING_SERVER_DOWNLOAD_TIMEOUT` | таймаут скачивания файлов, с | 600 |
| `TRAINING_SERVER_DOWNLOAD_LIMIT_MB` | порог размера файла (подтверждение оператора), МБ | 200 |
| `PULT_LOG_LEVEL` | `DEBUG`/`INFO`/`WARNING`/`ERROR` | INFO |
| `PULT_LOG_BODIES` | сохранять тела запросов/ответов | true |
| `PULT_BODY_LIMIT` | лимит тела в журнале, символов | 4096 |
| `PULT_JOURNAL_MAX` | записей журнала в памяти | 5000 |
| `PULT_LOG_ENQUEUE` | асинхронная запись журнала (false — журнал не теряется при аварии) | false |
| `PULT_POLL_INTERVAL` | интервал поллинга задач, с (этап T4) | 2.0 |

## Журналирование (FR-T6)

* `acceptance_data/logs/app.log` — текстовый журнал (ротация 10 МБ × 10, UTF-8);
* `acceptance_data/logs/session_<id>.jsonl` — структурный журнал сессии: события
  `pult_started`, `session_*`, `stand_*`, `http_request`/`http_response`/`http_error`,
  `journal_cleared`, … с полями `session_id`, `check_id`, `module`, `event`, `payload`;
* каждый HTTP-обмен фиксируется логирующим транспортом: метод, путь, query, метка
  проверки, статус, длительность, размеры, `Content-Type`, тела (text/json/csv —
  до лимита; бинарные данные — только размером);
* события записей (этап T1): `records_loaded`, `records_refreshed`, `record_download`,
  `record_download_failed`, `record_markup_stats`, `record_override`,
  `record_override_reset`, `records_manifest_saved`, `artifact_saved`, `api_note_created`;
  HTTP-запросы экрана помечаются метками `TC-REC-01…TC-REC-05` (фильтр в журнале);
* события консоли и замечаний (этап T2): `console_request` (операция, класс безопасности,
  подтверждения, карточка запуска, статус, запись журнала), `console_response_saved`,
  `console_attachment`, `api_note_created`/`api_note_updated`/`api_note_removed`,
  `notes_export_saved`; вызовы консоли помечаются меткой проверки (`TC-…`, по умолчанию
  `TC-CONSOLE`) и дублируются в `console_calls` сессии; ручные записи истории сессии —
  `console_call`, `console_attachment`, `api_note*`;
* журнал испытаний пишется синхронно (по умолчанию), чтобы не терялся при аварии.

## Тесты

```powershell
python -m pytest                       # unit + smoke (без сети)
$env:TRAINING_SERVER_BASE_URL = "https://energomera.ai-center.online"
python -m pytest -m integration        # живые проверки (только чтение)
python -m ruff check . ; python -m mypy client lib acceptance tests
```

Смоук-тесты запускают приложение через `streamlit.testing.v1.AppTest` с подменённым
транспортом httpx, поэтому не зависят от стенда. Интеграционные тесты T0–T2
**не выполняют** изменяющих и ресурсоёмких операций (кроме одного небольшого
markup-файла для проверки разбора разметки): консоль запросов проверяется только
на читающих операциях (`/health`, реестр файлов, 404 на скачивание неизвестного `id`).

Реестр эндпоинтов консоли генерируется из спецификации — при обновлении `docs/SOM1.json`
его нужно пересобрать:

```powershell
python -m tools.gen_endpoints           # пересобрать реестр 32 операций + ruff format
python -m tools.gen_endpoints --check   # сверка со спецификацией (для CI)
```

Живая проверка объединения без тестов:

```powershell
python -m tools.probe_records     # показатели записей, дубли, разбор разметки, дефект latin-1
```

## Ограничения

* **Субдатасеты в пульте не используются** (решение заказчика 15.09.2026): экран
  работает только с записями (RAW + markup), дублями и несопоставленными файлами;
  субдатасет остаётся перспективным требованием к API (`notes.PROSPECTIVE_REQUIREMENTS`).
* Ресурсоёмкие проверки (`train`, async-инференс, `fill` больших датасетов) —
  полноправная часть **сессий испытаний**, но не автотестов пульта: автотесты
  выполняют только чтение и `POST /api/tasks/test` с малой длительностью.
* С этапа T2 пульт может выполнять **любую** операцию API (включая изменяющие и
  ресурсоёмкие), но только осознанно: класс безопасности виден на экране, изменяющие
  операции требуют подтверждения и префикса `__TEST__` у имён создаваемых сущностей,
  удаляющие — чекбокса, слова `DELETE` и повторного ввода `id`, ресурсоёмкие — карточки
  запуска. По умолчанию (в автотестах и живых прогонах этапа) выполняются только
  читающие операции и `POST /api/tasks/test`.
* Известные дефекты API (скачивание не-ASCII, отсутствие `Range`, `limit/offset`
  у файлов, `phase_connection`, связи «датасет ↔ файлы») фиксируются как
  «блокировано API» + замечание — это результат испытаний, а не ошибка пульта.
  По реестру на 15.09.2026 не скачиваются **108 из 129** записей (не-ASCII имена).
* Крупные RAW (до 2.1 ГБ) не скачиваются без явного подтверждения оператора;
  адрес испытуемого сервера и уровень журнала задаются в `.env`.
* Скрипт Streamlit выполняется при подключении браузера: файлы журнала за текущий
  запуск появляются после открытия UI (проверка — `python -m pytest` и открытие
  пульта в браузере).
